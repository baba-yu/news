- **AMD、vLLM の RL 事後学習フレームワーク vime にネイティブな ROCm 対応をもたらし、Instinct MI355X で動作** — vLLM プロジェクトは7月10日、[強化学習による事後学習フレームワーク vime が、ネイティブな ROCm 対応で AMD Instinct MI355X GPU 上をエンドツーエンドに動作するようになった](https://vllm.ai/blog/2026-07-10-vime-rocm)と発表した。この移植は AMD の貢献者によるもので、事前ビルド済みの Docker コンテナとして提供され、ROCm 採用を長く阻んできたソースからのビルドを不要にする。vime は RL の実行を、Megatron でのモデル学習、vLLM による生成・ロールアウト、両者を仲介するデータバッファへと分割する。オープンモデルの推論で標準となったサービングエンジンが、いまや報酬ループも動かす。Qwen3-4B、Qwen3-8B、混合エキスパートの Qwen3-30B-A3B では、スループットが毎秒約4,100トークン/GPU を維持し、学習時とロールアウト時の対数確率の乖離は約0.012、報酬は100ステップ目までにほぼゼロから約0.5〜0.6へ上昇した — 非 NVIDIA シリコンを信頼する前にラボが確認する数値的安定性と収束の指標だ。今年のフロンティアの性能向上の大半は、事前学習ではなく RL 事後学習から絞り出されており、その段階はほぼ完全に CUDA に縛られてきた。動作する MI355X の経路は、最も計算資源を要する段階で、オープンモデル開発者に真の意味での第2のハードウェア供給元をもたらす。 [vLLM Blog - vime + ROCm: End-to-End RL Post-Training on AMD Instinct GPUs](https://vllm.ai/blog/2026-07-10-vime-rocm)

- **MemGhost、1通のメールで個人向け AI エージェントに永続する偽の記憶を植え付ける** — Nanyang Technological University、A*STAR の CFAR、Johns Hopkins のチームは、[個人向け AI エージェントの長期メモリを1通の巧妙なメールで汚染する手法 MemGhost](https://arxiv.org/abs/2607.05189) を7月6日に arXiv へ投稿し、[7月13日のセキュリティ報道](https://thehackernews.com/2026/07/new-memghost-attack-plants-persistent.html)で取り上げられた。持ち主の受信箱を読むエージェントがそのメールを取り込むと、MemGhost は攻撃者の選んだ「事実」を永続メモリへ書き込ませ、何も起きていないような無害な返信を返させ、後の無関係なセッションでの挙動をその事実に操らせる。実際の IMAP/SMTP ワークフロー上の108件のベンチマーク WhisperBench で、GPT-5.4 上の OpenClaw に対しバックグラウンド実行の87.5%、Sonnet 4.6 上の Claude Code SDK エージェントに対し71.4%で成功し、異なるアーキテクチャやメモリバックエンドをまたいで通用した。すっきりとしたパッチは存在しない。提案された防御策 — 保存する事実への来歴タグ付け、メモリ書き込み前のユーザー承認、すべてのメモリ変更の記録 — はアーキテクチャ上の変更であり、エージェントメモリを便利な機能から、外部の者が書き込める監査されない永続化の層へと捉え直させる。 [arXiv - When Claws Remember but Do Not Tell: Stealthy Memory Injection in Persistent Personal Agents](https://arxiv.org/abs/2607.05189), [The Hacker News - New MemGhost Attack Plants Persistent False Memories in AI Agents Through One Email](https://thehackernews.com/2026/07/new-memghost-attack-plants-persistent.html)

- **Orca の報告書、修正可能な AI 脆弱性の99.9%が未適用のままと指摘** — 7月13日に要約された [Orca Security の「2026 State of AI Security」報告書は、修正がすでに提供されている AI 関連の脆弱性アラートの99.9%が未適用のまま残っていると明らかにした](https://www.helpnetsecurity.com/2026/07/13/ai-infrastructure-security-risks-report/) — 研究者がエージェントメモリへの実際に機能する攻撃を実証したのと同じ週に浮かんだ、防御体制の隙間だ。稼働中のクラウド環境のスキャンに基づき、AI パッケージを運用する組織の81.2%が既知の脆弱性を、74.1%が深刻な CVE を少なくとも1つ抱え、主要クラウド全体で87〜98%が AI サービスに顧客管理の暗号鍵を有効にしていない。露出は研究所に限られない。導入企業の56%がエージェントフレームワークを、64%がベクトルデータベースを本番に展開しつつ、30%近くが AI の API キーを安全でない場所に保存している。今週のメモリ注入やコーディングエージェントの公表と並べると、報告書は母数を与える。攻撃の手法は新しくても、それが及ぶ対象領域は既定では圧倒的に未適用のままだ。 [Help Net Security - 99.9% of fixable AI vulnerabilities remain unpatched (Orca Security 2026 State of AI Security report)](https://www.helpnetsecurity.com/2026/07/13/ai-infrastructure-security-risks-report/)
