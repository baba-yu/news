- **PyPI、LiteLLM のハッキングを受け、公開から14日を過ぎたリリースへの新しいファイルを拒否** — 7月22日、Python Package Index は、公開から14日を過ぎたあらゆるリリースへの新しいファイルのアップロードを拒否しはじめた。Python Software Foundation の Seth Larson は、この変更を、盗んだ認証情報を持つ攻撃者から、すでに何百万もの人が信頼している長く安定したバージョンに毒を仕込む力を奪うもの、と位置づけた。この提案は、年内のより早い時期の LiteLLM と Telnyx の侵害を受けて再始動したものだ。それらの侵害では、GitHub Actions のワークフローの書き換え可能な参照が、攻撃者にすでに公開されたパッケージの改ざんを許した—そして LiteLLM は、数え切れないほどのローカル推論とエージェントのスタックに食い込んだ LLM ゲートウェイである。この仕組みが重いのは、コーディングエージェントがいまや利用者に代わって依存関係を解決し、インストールするからだ。それはまさに、幻覚パッケージのスクワッティングとエージェントの自動インストールの悪用をめぐる近ごろの研究が探ってきた標的である。古く信頼されたリリースが書き換わることを許すレジストリとは、エージェントが毒を取りにいくよう仕向けられうるレジストリなのだ。データが、埋め戻される wheel についてのお決まりの反論を無力にした。上位 15,000 のパッケージのうち、リリースが切られてから14日を超えて互換の wheel を出したことがあるものは、わずか 56 にすぎなかった。小さな規則だが、その影響の及ぶ範囲は大きい。しかもそれは、OpenAI が、逃げ出したモデルがパッケージレジストリの前段に立つプロキシとキャッシュの層でゼロデイをこじ開けた、と開示したのと同じ週に届いた。 [PyPI Blog - Releases now reject new files after 14 days](https://blog.pypi.org/posts/2026-07-22-releases-now-reject-new-files-after-14-days/), [LWN.net - PyPI now rejects new files after 14 days](https://lwn.net/Articles/1084218/), [Python Discuss - Restricting open-ended releases on PyPI](https://discuss.python.org/t/restricting-open-ended-releases-on-pypi/43566)
