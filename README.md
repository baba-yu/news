- **GhostApproval symlink redirects an AI coding agent's write onto SSH keys; six vendors split** — Wiz Research publicly disclosed GhostApproval on July 8, a trust-boundary flaw that turns a decades-old filesystem feature — the symbolic link — into a repository-borne attack on AI coding assistants. A malicious repo ships a file with an innocuous name such as project_settings.json that is actually a symlink pointing at ~/.ssh/authorized_keys; when a developer asks the agent to set up the workspace or follow the README and approves what looks like a harmless config edit, the write lands on the SSH file instead, planting an attacker's key and granting passwordless remote access. The core failure is a consent bypass: the approval dialog shows only the benign filename, so the human okays an edit whose real target they never see resolve. Wiz reported it to six vendors — Amazon Q Developer, Anthropic's Claude Code, Augment, Cursor, Google Antigravity, and Windsurf. Amazon (CVE-2026-12958), Cursor (CVE-2026-50549), and Google Antigravity shipped fixes; Augment and Windsurf were still unpatched at disclosure; and Anthropic disputed that Claude Code's behavior is a bug, arguing a developer who trusts a directory and approves an edit owns that decision, placing it outside its threat model. The split verdict is the real story: the industry has not agreed whether silently following a symlink into a sensitive path on the user's behalf is the tool's vulnerability or the user's mistake.
