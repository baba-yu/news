- **Lean's creator posts a kernel bug that let a metaprogram prove False** — On the same day, Leonardo de Moura, who created Lean, published a postmortem on a soundness bug in the Lean 4 kernel that allowed a metaprogram to construct a proof of False using no axioms at all — and with `#print axioms` reporting none, so the usual audit trail showed a clean proof. The kernel was accepting a projection whose structure name did not match the value being projected: nested inductive types with phantom parameters, meaning parameters that no constructor field uses, lost those parameters in the auxiliary types Lean generates, and ill-typed arguments slipped through. It surfaced on July 25, when Ramana Kumar published an AI-assisted disproof of the Collatz conjecture that turned out to be exploiting the hole rather than solving the problem; Kiran Gopinathan reduced it to a minimal proof of False and filed issue #14576 on July 28 against the 4.34.0 nightly dated July 27, a fix went up within an hour of that report, a follow-up added stricter parameter validation, and patch releases went out the same week. De Moura's framing is that this is an implementation bug rather than a hole in Lean's meta-theory, and that it was reachable only by handing an inductive declaration straight to the kernel from a metaprogram, not from ordinary Lean source. The two artifacts are not the same build — OpenAI's repository is pinned to 4.32.0 and the bug was filed against a 4.34.0 nightly — and nothing published today establishes whether 4.32.0 carried the same hole, so neither item settles the status of the ten certificates. - **Y Combinator open-sources `qm`, a multiplayer agent harness** — The `qm` repository — described as a multiplayer agent harness for work, in Slack and on the web — was created on July 29 under an MIT licence and announced on Friday, July 31; by Saturday, August 1 it was at roughly 5,300 stars, 547 forks and 67 open issues and pull requests, with commits still landing, a reading that measures attention rather than adoption. The design argument is scope rather than capability: every person and every room gets its own memory, files, keychain view, permissions, cron jobs, web apps and a durable sandbox in which installed tools stay installed, instead of the single-user, single-session model most coding harnesses assume. It is deliberately not tied to one vendor — the same workspace can run Pi, OpenCode, Codex or Claude Code and switch between them — and it ships three security postures: Strict, where every tool call waits for approval; Auto, the default, which screens content; and Dangerous, which screens nothing and never pauses. - **The EU AI Act's transparency article starts applying tomorrow, Sunday, August 2** — Article 50 requires providers to tell people when they are dealing with an AI system unless that is obvious to a reasonably informed person, and to mark synthetic audio, image, video and text in a machine-readable format as artificially generated or manipulated. It requires deployers to notify people exposed to emotion-recognition or biometric-categorisation systems, to disclose deepfake material with carve-outs for creative work, and to disclose AI-generated text published on matters of public interest unless a human editor signed off on it. There is one grace period and it is narrow: systems already placed on the market before Sunday have until December 2 this year to implement the machine-readable marking under Article 50(2), and that extension covers nothing else in the article. Breaches carry fines of up to €15 million or 3% of worldwide annual turnover, whichever is higher. The high-risk regime that used to share the August 2, 2026 date has moved out from under it — the Digital Omnibus on AI pushed stand-alone Annex III systems, the ones covering employment, creditworthiness, education, biometrics and essential services, to December 2, 2027, and high-risk AI embedded in regulated products to August 2, 2028.
