木曜日の動きは、構造の異なる2つの層に整理できる。連邦レベルの AI 統治の青写真と、フレームワークレベルの生きたエージェント型セキュリティ群だ。そしてその下を、1件のオープンウェイトモデルの発表が、土台となるローカル基盤の物語として貫いている。6月4日に Jay Obernolte 下院議員と Lori Trahan 下院議員が公開した「Great American AI Act」のたたき台が、本日の統治面の軸だ。およそ270ページの本文は、フロンティアモデル開発を規制する州法を3年間先取りすること(カリフォルニア州の訓練データ開示法 AB 2013 と SB 942 のウォーターマーク規定の一部を直接の標的にする)と引き換えに、連邦レベルの情報開示の下限を求める。前年度の総収益がおよそ5億ドルを超える開発者はすべて、破滅的リスク(大量死をもたらす予見可能で重大なリスクと定義される)をどう評価・管理するかを記述した公開 frontier AI framework を公表しなければならない。あわせて、Center for AI Standards and Innovation を商務省内に、2027〜2029会計年度に年1億ドルで法制化する。この1つの文書が、本日で最も整合度の高い裏付けを担う。フロンティアラボの統治フレームワークが共通の定量的な有害性の閾値へ収束するという予想(5月29日)に対し、関連度5で当てはまる。基準額を超える各社へ一律に適用される開示テンプレートこそ、個別に構築された安全フレームワークを共通の定量的な破滅的リスクの形へ押し進める構造的な力そのものだからだ。さらに、AI 検索ベンダーが連邦・EU・州の3正面の規制に直面するという予想(5月31日)の連邦・州の柱も厚くする。ただし動くのは米国の正面だけで、欧州側は手つかずのままだ。

本日の2つ目の構造的な軸は、エージェント型AIのセキュリティ群だ。新たに公開されたアドバイザリーは、Langroid の SQLChatAgent における CVE-2026-25879 を CVSS 9.8 のクリティカルと評価する。このエージェントはモデルが書いた SQL を実行し、それをプロンプトインジェクションが誘導できる(悪意あるプロンプトで直接、あるいはモデルが後で読むデータを汚染して間接的に)。そのため攻撃者は、方言ごとの危険なプリミティブ(PostgreSQL の pg_execute_server_program、MySQL の FILE、MSSQL の xp_cmdshell)を実行させ、エージェントが過剰な権限を持つロールで動いていれば、データ窃取からデータベースホスト上のリモートコード実行へと昇格させられる。Langroid 0.63.0 の修正は、エージェントの既定を、sqlglot で構文解析した SELECT のみの許可リストと、方言を意識した危険パターンの拒否リストに変える。アドバイザリーはこの欠陥を、実際に悪用されている LiteLLM プロキシのインジェクション CVE-2026-42208 と結びつける。そこでは細工された Authorization ヘッダがパラメータ化されていない鍵照会クエリに到達した。両者は同じ「テキストから SQL、そしてデータベースへ」の経路をたどり、1つの教訓を浮かび上がらせる。SQL を書くことを許す LLM はすべて、最小権限で既定が読み取り専用のロールに対して動かさなければならない、という教訓だ。この群は4つの検証行に効いている。エージェントハーネスのベンダーが gVisor+OS サンドボックス+VM の封じ込め仕様を出荷するという予想(5月31日)に、関連度4で当てはまる。Langroid の修正は、封じ込めを展開者まかせにせず、既定でハーネス側へ移すからだ。これは名指しされた隔離プリミティブの、構文解析・許可リスト型の対応物だ。さらに、AI 支援の脆弱性トリアージが連邦・金融・保険の基準を支えるという予想(6月1日)に脅威の材料を供給し、BadHost CVE-2026-48710 の再採点という予想(6月2日)の背後にある、方向性としての深刻度上昇の前提を支える。ホストの RCE への連鎖がたどれた時点で、Langroid がいきなり CVSS 9.8 として公開されたためだ。

同じ群が、本日の2件の休眠予想の復活も駆動する。LLM ツール群と Linux カーネルの CVE 連鎖が支配的な攻撃パターンになるという予想(5月2日)は、直接の一致で復活する。自身のシグナル集合が LiteLLM CVE-2026-42208 を挙げており、本日のニュースがまさにその CVE を再び名指しした。いまや実際に悪用され、Langroid と対になっている。連鎖の一致は LLM ツール群側の半分で成立する一方、Linux カーネルのローカル権限昇格という対の柱は現れない。Agent-in-the-Loop の機密持ち出しが CIS/OWASP のリスクリストで首位になるという予想(4月20日)は、第2層の意味的一致で復活する。Langroid の欠陥は、注入された内容に誘導された組み込み型のエージェントが、自らが特権アクセスを持つデータを持ち出したり破壊したりする明快な実例だからだ。ただし本日の位置づけは、リスク順位を駆け上がる CI・機密漏えいではなく「プロンプトから SQL、そして RCE」だ。

両方の軸の下を貫くように、中国の MiniMax が M3 を発表した。フロンティア級のコーディングエージェント性能、100万トークンのコンテキストウィンドウ、ネイティブのマルチモーダル性を兼ね備えた初のオープンウェイトシステムとうたう。これは新たな MiniMax Sparse Attention 機構の上に構築され、選んだ区間だけを採点して二次的なアテンションのコストを回避する。報道によれば、およそ100兆のテキスト・画像を交互に並べたトークンで、前世代の M2.7 のおよそ20分の1のトークン当たり計算量で訓練されたという。SWE-Bench Pro で 59.0% を記録し、GPT-5.5 と Gemini 3.1 Pro を上回り、Claude Opus 4.7 に迫るとし、BrowseComp では 83.5 をうたう。これは、中国のオープン MoE 陣営が OpenRouter シェアの15%下限を突破するという予想(5月28日)に、供給側の勢いとして関連度4で当てはまる。ただし本日で最も鋭い留保が伴う。スコアは MiniMax 自社のインフラ上で同社が報告したもので、モデルは MiniMax の API と Code アプリ経由でしか利用できず、およそ10日以内に Hugging Face で公開すると約束されたウェイトと技術報告はまだ出荷されておらず、公開済みの最新チェックポイントは M2.7 のままだ。本日の流れを横断するパターンは、最も強い2つのシグナルが、同じエージェント型AIの土台の、対極にある統治の軸に位置していることだ。連邦の破滅的リスク開示の体制が上から固まる一方で、生きた「プロンプト注入から RCE」のクラスが実行層の防御を下から固める。そしてオープンウェイトモデルの発表は、チェックポイントが出荷されるまでは、ルーティング可能な成果物ではなく注視すべきベンチマークの主張にとどまる。


## Relation to My Own Predictions

ユーザーの1つ目の継続予想(悪意あるローカル LLM がマルウェアになること、およびゼロトラストが根本的な防御になること)は、武器化と構造的防御の両方の柱で、ここ数週間で最も直接的な裏付けを得た。攻撃面の柱では、本日、生きたエージェントスタックの悪用クラスが姿を現した。Langroid の SQLChatAgent における CVE-2026-25879 は CVSS 9.8 となった。プロンプトインジェクションに誘導されたモデル製の SQL が(直接、あるいはモデルが後で読むデータを汚染することで)、過剰な権限を持つデータベースロール(PostgreSQL の pg_execute_server_program、MySQL の FILE、MSSQL の xp_cmdshell)を通じてホスト上のリモートコード実行へ昇格するからだ。アドバイザリーはこれを、実際に悪用されている LiteLLM プロキシのインジェクション CVE-2026-42208 と対にしている。これはまさに、この予想が追うエージェント型AIのワークフロー基盤の CVE の波だ。構造的防御の柱では、Langroid 0.63.0 の修正が、既定でハーネス側へ移ったゼロトラストの答えだ。sqlglot で構文解析した SELECT のみの許可リストと、方言を意識した拒否リストを備え、LLM が書いた SQL はすべて最小権限で既定が読み取り専用のロールに対して動かす、という明示のルールを伴う。これはモデルの出力を、信頼できず攻撃者に操作されうる入力として扱う姿勢であり、この予想が構造的な到達点として指す、能力ごとに門を設ける構えだ。本日は両方の柱を同時に補強する。武器化側では汚染入力から RCE への攻撃連鎖、防御側では既定の最小権限による封じ込めのプリミティブだ。ただしここでの答えは SQL 許可リストのガードであって、署名付きチェックポイントや証跡ログ、調達ゲートのプリミティブではない。MCP サーバの隔離テレメトリや、連邦の CVE 拒否リストの強制も本期間には現れなかった。

ユーザーの2つ目の継続予想(高度な用途にはクラウド API、日常用途にはローカル LLM、SaaS 値上げに駆動される)は、モデル側からローカル基盤の進展を、規制側から逃げ場のない圧力としての入力を得た一方、クラウド API の柱は本日は静かだった。ローカル LLM の柱では、MiniMax M3 が動作範囲を広げるシグナルだ。SWE-Bench Pro で 59.0% とフロンティア級のコーディングエージェント性能をうたい、GPT-5.5 と Gemini 3.1 Pro を上回るとし、新たな MiniMax Sparse Attention 機構による100万トークンのコンテキストウィンドウとネイティブのマルチモーダル性を備え、前世代のおよそ20分の1のトークン当たり計算量で訓練された。これはまさに、日常用途・ローカルの柱が期待する、消費者がルーティングして使えるオープンウェイトの競合だ。端末上の計算の許容範囲を広げ続け、従量課金のクラウド API から汎用的なワークロードを引きはがしていく。ただしこのシグナルには、この予想にとって重い留保がつく。スコアは MiniMax 自社のインフラ上で同社が報告したものであり、モデルは MiniMax の API と Code アプリ経由でしか利用できず、およそ10日以内に Hugging Face で公開すると約束されたウェイトはまだ出荷されていない。そのため M3 は、まだ自前で運用できないながらも、ローカル基盤の物語を強める。逃げ場のない圧力の側では、Great American AI Act のたたき台が課す、収益5億ドルを基準とする破滅的リスク開示の義務が、フロンティアラボがクラウド API の柱で負うコンプライアンス負担を引き上げる。これは、この予想が言うところの、ハイパースケーラー規模でしか割に合わない規制対応のコストであり、日常のワークロードをローカルへ向かわせる価格勾配を間接的に急にする。本日は、信頼できるが未出荷のオープンウェイトの競合を通じて日常用途・ローカルの半分を補強する一方、SaaS 値上げという圧力は、新たに値が出たわけではなく、コンプライアンスの経済性を通じて示唆されるにとどまる。

ユーザーの3つ目の継続予想(RL/LLM ベースの予測性能の向上)は、本日は薄い土台の柱の進展と統治の柱の進展だけを得て、実世界への展開の柱と RL 固有のシグナルは欠けている。土台の側では、MiniMax M3 のアーキテクチャが部分的で間接的な一致だ。MiniMax Sparse Attention 機構が100万トークンのウィンドウに達した点や、フロンティア級のコーディングエージェントと自律的なウェブ検索の BrowseComp 83.5 のスコアは、予測の土台の柱が支配的なパラダイムとして指す、超長コンテキストかつ多段のエージェントの土台を指し示す。ただし正直なところ、これはアーキテクチャとベンチマークの主張であって、ルーターのみの LoRA や、ルーターを意識した優位性の分解、超長コンテキストでの RL 安定性の成果ではなく、ウェイトも未出荷のままなので、土台のシグナルは弱い。統治の側では、Great American AI Act のたたき台が義務づける公開 frontier AI framework と、法制化された Center for AI Standards and Innovation が、自律的な予測エージェントがいずれその内側で動くことになる、調達ゲートと能力開示の境界だ。ただしこれらは連邦の開示体制であって、この予想が追う NIST の非人間アイデンティティ管理プロファイルや、正式な能力証明の枠組みではない。本日のこの予想に対するシグナルは本当に薄い。RL 訓練のプレプリントも、署名付きスキルレジストリの相互運用もなく、Tesla Optimus、Figure、Foxconn の陣営からヒューマノイドの量産ラインや OEM のポリシー LoRA の決着も本期間には現れなかった。そのため本日は土台と統治の柱に間接的に触れるだけで、実世界への展開の柱は動かないままだ。
