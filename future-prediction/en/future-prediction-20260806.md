## Summary of Findings

Thursday, August 6 is a day about the distance between a name and what that name runs, and the clearest statement of it is a measurement rather than a product. Alex Wauters published an analysis on the Scale X blog on Wednesday, August 5 of an interactive browser game in which the player stands in for the human approver of a coding agent, accepting or denying each command under time pressure. Across more than 40,000 runs and roughly 409,000 approve-or-deny decisions, mean accuracy was 66.3%. The mean is not the finding; its shape is. The miss rate rose as a hostile command looked less hostile: 11.7% on obviously destructive commands, 23.8% on persistent mutation attacks, 33.4% on exfiltration and code execution, and 35.0% on scope violations. 35.2% of players caught every threat, but only 20.8% did so while blocking no more than one in five safe commands, which is the difference between a careful reviewer and someone denying on sight; 7% approved everything put in front of them, and 32.9% of sessions ended on a negative score. The single most-missed command was npm run analyze, approved 64.7% of the time even though the malicious payload was visible in the history log rather than in the string the player was asked to judge. The author states the artificiality himself and it belongs in the same breath: threats appeared in 34% of commands, far above any real workload, and a timed game is not a working day. His own conclusion is where the day turns, which is to put the check in the tool layer, where the payload is inspected, rather than in the approval prompt, where only the command line is. A person asked to approve a name cannot inspect what the name resolves to, and that is not a training deficit and does not improve with a clearer prompt.

What shipped this week does not do that, and both items describe the layer such a check would have to live in. Meta's research group published Muse Code and Muse Spark 1.2 on Wednesday, August 5. Muse Code is a terminal coding agent, explicitly labelled beta rather than generally available, installed on macOS and Linux by piping an install script from dev.meta.ai, and built to plan changes, write code and validate the result across large repositories while coordinating specialised subagents. Two properties are stated as headline design. The subagents are asynchronous and persist for the whole session rather than being spawned per task, and they decide themselves when to report back to the main agent, which is what removes round-trip latency from multi-step problems. And every model call, tool run, approval and edit is appended to a local event log, which Meta describes as making the agent replay-exact and restart-safe, so after a crash it resumes precisely where it stopped rather than re-deriving state from the working tree. Muse Spark 1.2 is the model underneath, available now inside Muse Code and through the Meta Model API; the announcement names Terminal-Bench 2.1, DeepSWE 1.1 and Meta's internal coding benchmark as its comparisons but does not state the scores, so nothing published there ranks against another harness.
