1. Hugging Face's downloader ships no default XET-to-HTTP fallback by Q2 2027

   Alibaba took Qwen3.8-Max generally available on Monday, August 3 at 2.4 trillion total parameters with roughly 95 billion active per token, and said it will open the weights next week alongside a smaller Qwen3.8-27B. The same day, Unsloth published 2026.8.2 to PyPI, one release after 2026.8.1, and the substance of it was not a kernel and not a new model family. Downloads now fall back automatically from XET, the transfer path Hugging Face uses in place of a plain file pull for large repositories, to ordinary HTTP when XET stalls, with transfer memory much reduced. The release note is one line: "Unsloth now auto fallbacks to HTTP if XET stalls." A project whose reason to exist is making training fit on smaller hardware spent a release making a download finish.
   
   The prediction is about where that fix does not travel. Through the close of Q2 2027, huggingface_hub's default download path still does not recover a stalled XET transfer by finishing the same file over plain HTTP. Recovery work stays inside XET — more retries, better stall detection, chunk-level resume, faster delivery infrastructure — and the cross-protocol bail-out stays where Unsloth put it, in the project holding the file.
   
   Today the client has no such thing, and the shape of the code says why. The download path decides once, before any bytes move: if the repository is XET-backed and the hf_xet package is present it calls the XET getter, otherwise it calls the HTTP getter, and there is no handler between them that could move a file from the first to the second mid-flight. The one place the path uses the word fallback is a warning aimed at a machine where hf_xet was never installed — XET is enabled for the repository, the package is missing, so it is falling back to regular HTTP download. That is a fallback for a client that never had the fast path, not for a transfer that lost it. HF_HUB_DISABLE_XET expresses the same limit: it changes which path is chosen, not what happens when the chosen path dies.
   
   The failure it would guard against is not hypothetical. Two open reports on huggingface_hub's own tracker say so. Issue #4520, filed on July 11, has progress bars and the XET log simply ceasing to update on a large pull. Issue #4349, filed on June 12, is the detail that makes a fallback harder than it sounds: with XET already disabled, the plain HTTP path has no automatic retry of its own, dying at 17.3 of 42.5 gigabytes with nothing left in the cache to resume from. The escape hatch is not obviously more reliable than the thing it escapes.
   
   The force holding the fix inside XET is that XET is the product, not a transport detail. It is the path Hugging Face built to replace an ordinary file pull for exactly these repositories, and a default that abandons it the moment it stalls does three things at once: it concedes in shipped code that the storage layer cannot be trusted with the artefacts it was built for, it throws away whatever partial state the transfer had and restarts the file whole on a slower route, and it removes the pressure that produces the real fix. Vendors ship the retry. They do not usually ship the admission.
   
   Scale is what turns an annoyance into a structural gap. Kimi K3's published weights ran to 1.56 terabytes across 96 shards; a 2.4-trillion-parameter artefact sits in the same class, and the 27B sibling shipping beside it is a statement about who the flagship is actually for. At that size a pull is not a click but a job that runs for hours over a link that will drop at least once, and the chance of a clean first attempt falls with every shard. The parties absorbing that are not individuals pulling weights onto one machine — they are the intermediaries who fetch the reference weights once and republish something smaller, which is the population Unsloth serves and the reason its release notes have started to read like a transfer library's.
   
   What settles this is a shipped version, not a roadmap. The prediction is wrong if, on or before the close of Q2 2027, a released huggingface_hub detects a stalled or failed XET transfer and completes that same file over the plain HTTP endpoint with no environment variable set and no exception handling written by the caller, visible in the release notes or in the download path itself. Three things do not count against it. More retries, better stall detection, chunk-level resume or faster infrastructure inside XET are the predicted outcome rather than its negation. A friendlier HF_HUB_DISABLE_XET is still a decision taken before the first byte moves. And further downstream projects shipping their own bail-out — a serving runtime, a local runner, a mirror — confirm the claim rather than break it, because the point is that this keeps being written by whoever is receiving the file rather than by whoever is sending it.

   In plain language: Downloading giant AI models often stalls, and Hugging Face will keep fixing its own system rather than switching to the plain old download method.

Nobody held it yet, and CREST expected its first accredited organisation within about a month. What that document does is convert the one thing a bundled product cannot supply into something a buyer can put on a purchase order: independently assessed, held by a named company, and about the conduct of the engagement rather than the strength of the tooling. Four things do not count. General CREST penetration testing accreditation held without the new AI additions does not count, because it predates the question. 3. Agent-written accelerator stacks get an independent serving number by Q2 2027

   Jeremy Nixon, who left Google Brain to found Infinity last year, says his team pointed AI coding agents at d-Matrix silicon and had CUDA-equivalent software running in roughly ten hours, reaching about 92 percent of the Corsair part's theoretical peak on tensor-parallel matrix multiplication. Within ten days, he says, three frontier models were running end to end on the chip with every layer written from scratch. The agent doing the writing, Ignition, generates, tests and tunes the compute kernels that decide how efficiently an accelerator runs a model — historically the work that costs a challenger vendor a specialist team and several years, and the reason porting so rarely happens at all. Infinity closed a 15 million dollar seed at a 100 million valuation last month.
   
   Every figure in that account is first-party, and the two claims inside it are not the same claim. Ninety-two percent of theoretical peak is a ratio against the arithmetic the silicon could in principle issue, measured on one kernel class, on a shape and a precision the kernel author selects, with the data already where it needs to be. That is a real engineering result and it is also the most flattering number available on a new part. End-to-end serving is a different measurement and a harder one: a named model at a stated precision, batch size and context length, carrying attention, key-value cache traffic, sampling, and the long tail of operators a matrix-multiply benchmark never touches. A stack can sit near peak on the kernel that matters most and still lose on tokens per second, because the operators nobody benchmarked are the ones that stall. Nixon's stronger claim — three models running end to end inside ten days — is the one that would settle the argument, and it arrived without a throughput figure beside it.
   
   The same news cycle carried the disagreement about where the moat now sits. Rebellions' Marshall Choy says CUDA is no longer a factor for inference. Modular's Chris Lattner reads CUDA's graphics inheritance as a burden it cannot shed. Futurum's Daniel Newman points the other way, at NVIDIA's December purchase of SchedMD, which maintains the Slurm scheduler, and argues the moat moved up the stack rather than drained out of it. Argument does not resolve this. What resolves it is whether someone evaluating a challenger part can find a serving number they did not have to take from the seller.
   
   So the prediction lands on who publishes, not on who is right. By the end of Q2 2027, a publicly readable artefact reports end-to-end inference throughput or latency for a named model running on a named non-NVIDIA accelerator whose kernel or compiler layer is stated to be machine-generated, and discloses the run configuration — model, precision, batch size or concurrency, sequence length — closely enough that a reader could attempt the same run. The publisher holds no commercial stake in either the silicon or the code generator: an academic group, an independent evaluation body, or a customer reporting its own measurement. One edge case is settled in advance rather than after the fact — a result carried in an MLCommons Inference round counts, even though the submitter runs the hardware, because the disclosure requirements and the review belong to the consortium and not to the submitter. How the stack was produced is irrelevant to the bar: an agent emitting Triton or MLIR counts exactly as much as an agent emitting hand-shaped kernels, provided the publication states that the layer was machine-written.
   
   It resolves false if no artefact meeting all of those conditions is public on 30 June 2027, and there are three unremarkable ways that happens. The party best placed to run the measurement is the one selling the part, and independent evaluators tend to arrive after a buyer base exists rather than before it, so the whole corpus could still be vendor blogs, press releases, keynote slides and founder interviews, however detailed those get. Percent-of-peak has gravity of its own — it is cheap, it flatters, and it is what a seed-stage company can produce in a week — so the microbenchmark may simply keep being the number everyone quotes. The third route is worth naming because it is not a defeat for the underlying thesis: the field may settle on operator coverage as the honest metric, meaning how much of a framework's surface a generated stack actually implements, and report that in place of throughput. If that is what happens and no serving number appears from an unaffiliated publisher, this still resolves false.

   In plain language: A start-up says AI wrote chip software in ten hours. Someone with no stake has to measure it before it counts.

### A founder says coding agents rebuilt a CUDA-equivalent stack for someone else's accelerator in about ten hours
