- **Tinatamaan ng BadHost host-header flaw sa Starlette ang LLM serving stack** — Pinatatalas ng sariwang pagsusuri ngayong linggo ang lawak ng pinsala ng BadHost (CVE-2026-48710), isang host-header injection flaw sa Starlette ASGI framework — ang routing core sa ilalim ng FastAPI — na nagbibigay-daan sa isang umaatake na kontrolin ang path na pinupuntahan ng isang request sa pamamagitan ng pagpasok ng iisang karakter sa HTTP Host header, na tinatalo ang anumang path-based authentication middleware. Humihila ang Starlette ng humigit-kumulang 325 milyong download bawat linggo, at umaabot ang flaw nang direkta sa local-LLM serving stack: natuklasan ito ng German security firm na X41 D-Sec sa isang OSTIF-sponsored na audit ng vLLM, at sumasaklaw ang apektadong bahagi sa FastAPI, vLLM, LiteLLM, at mga MCP server — na ang spec ay nag-aatas ng unauthenticated na OAuth discovery endpoints, na nagbibigay sa mga umaatake ng maaasahang ruta ng pananamantala — kung saan iniuugnay ng mga mananaliksik ang primitive na ito sa authentication bypass, server-side request forgery, at sa ilang kaso ay remote code execution laban sa mga AI service na nasa mga internal na network nang walang proteksyon ng reverse-proxy, ayon sa [InfoQ - BadHost vulnerability exposes AI agents, evaluators, and LLM gateways](https://www.infoq.com/news/2026/06/badhost-ai-systems-vulnerability/). Inilabas ang pag-aayos sa Starlette 1.0.1 (inilabas Mayo 21, isang araw bago ang pampublikong disclosure), at ang praktikal na mitigation ay basahin ang request path mula sa ASGI scope sa halip na mula sa muling-itinayong URL sa anumang middleware na gumagawa ng desisyon sa seguridad; may libreng scanner na nakapaskil sa [BadHost - CVE-2026-48710 Starlette host-header auth bypass](https://badhost.org/). ## Future


1. Magiging default na makina ng GitHub Copilot ang Microsoft MAI coding model pagsapit ng Q4 2026

   Ginamit ng Microsoft ang Build 2026 keynote nito noong Hunyo 2 upang ipakita ang isang in-house na MAI model family na kinabibilangan ng isang coding-focused na model na tahasang inihanda upang patakbuhin ang GitHub Copilot, ang pinaka-direkta nitong hakbang sa ngayon upang bawasan ang pag-asa sa OpenAI para sa foundation-model na kakayahan. Isang araw bago nito, noong Hunyo 1, inilipat ng GitHub ang bawat Copilot plan sa usage-based billing, na pinapalitan ang flat-rate na premium request ng per-token na GitHub AI Credits at inaalis ang fallback na nagbibigay-daan sa mga user na naubusan ng kanilang allowance na bumaba sa isang mas murang model at magpatuloy sa pagtatrabaho. Ang dalawang pangyayaring ito ay kalahati ng iisang kuwento ng margin: inilalantad na ngayon ng metered na billing ang sariling gross margin ng Microsoft sa bawat agentic Copilot request, at ang isang first-party na model na hindi nito binabayaran ang OpenAI nang per-token ang pinakamalinis na palanca upang protektahan ang margin na iyon. Ang hula ay sa loob ng humigit-kumulang dalawang quarter ay gagawin ng Microsoft na default na makina ang MAI coding model sa likod ng mataas-na-dami na agentic path ng GitHub Copilot — code completion, ang autonomous na bug/feature/PR agent, at chat — na inililipat ang mga GPT-class na model sa isang premium o opt-in na tier sa halip na sa standard na path. Asahan na lalabas ang pagbabago bilang wika sa Copilot release-note o changelog na nagpapangalan sa isang Microsoft first-party na model bilang default para sa Copilot completions o agent mode, magkakaibang per-model token rates sa inilathalang GitHub AI Credits price table, at mensahe sa Build/Ignite na naglalarawan sa first-party inference bilang ang makina ng gastos sa ilalim ng bagong metered na mga plan.


   In plain language: Nagbabayad na ngayon ang Microsoft kada paggamit para sa GitHub Copilot, kaya tahimik nitong ililipat ang Copilot sa sarili nitong mas murang coding model bilang default.


2. Maglulunsad ang Snowflake ng isang metered na Claude-in-Cortex na governed-data agent tier pagsapit ng Q4 2026

   Sa Snowflake Summit Platform Keynote noong Hunyo 2, inanunsyo ng Snowflake ang direktang integration ng Claude ng Anthropic sa Cortex AI, na nagpapalawig sa humigit-kumulang $200M na partnership na nilagdaan ng dalawa noong Disyembre at nagbibigay-daan sa 13,900+ enterprise customer nito na magpatakbo ng mga Claude-powered na agent laban sa governed data nang hindi umaalis ang data na iyon sa platform. Umasa nang husto ang keynote sa compliance na anggulo — inilarawan ni Daniela Amodei ang tiwala bilang isang accelerant ng negosyo, at ang mga pinangalanang adopter na Carvana, eSentire, at Notion ang nag-aangkla sa pitch para sa regulated na industriya. Ang pagkakalarawang iyon ay magiging kita lamang kung mete-meter ito ng Snowflake: ang isang capability-partnership noong Disyembre kasama ang isang pinangalanang agent control plane (Snowflake Intelligence para sa mga knowledge worker, Cortex Code para sa mga engineer) ang paghahanda para sa isang consumption SKU, hindi isang libreng feature. Ang buong modelo ng Snowflake ay credit-based na consumption, at ang isang frontier-model na agent na tumatakbo laban sa governed tables ang pinakamataas-na-margin na compute na maibebenta nito. Asahan na gagawin ng Snowflake ang Claude-in-Cortex mula isang launch headline tungo sa isang naka-package, hiwalay-na-mete-meter na governed-data agent tier — na nakapresyo sa Snowflake credits kada agent run o kada token, na may kuwento ng no-data-egress na compliance bilang pampalakas na katwiran para sa mga mamimili sa finance, healthcare, at pampublikong sektor — at iuulat ito bilang isang pinangalanang linya ng paglago. Ang paglipat ng GitHub Copilot sa per-token na usage-based billing isang araw bago nagsesenyas ng parehong hilig sa industriya: ang agentic AI na kakayahan ay lumilipat tungo sa metered na consumption sa halip na flat-rate na pagsasama, at ang consumption-native na presyo ng Snowflake ang gumagawa rito bilang likas na template para sa pagkita mula sa isang hosted na Claude agent.


   In plain language: Inilagay lang ng Snowflake ang Claude sa data platform nito. Dahil naniningil ito ayon sa paggamit, malapit na nitong ibenta ang mga AI agent na iyon bilang isang bayad, mete-meter na add-on.


3. Itataas ang CVSS score ng BadHost CVE-2026-48710 nang higit sa 6.5 pagsapit ng Q4 2026

   Ang CVSS 6.5 base score na itinakda sa BadHost (CVE-2026-48710), ang Starlette host-header injection flaw, ay itataas patungong high severity pagsapit ng Q4 2026, kung saan alinman ay muling sko-skorin ng NVD ang record o maglalathala ang mga downstream na konsyumer ng mas mataas na vendor-specific na advisory. Ang mga nagdi-disclose na mananaliksik sa X41 D-Sec at OSTIF ay nakapagsabi na na ang 6.5 ay maliit kumpara sa downstream na epekto: ang isang iisang-karakter na Host-header primitive ay tinatalo ang path-based authentication middleware at iniuugnay sa authentication bypass, server-side request forgery, at sa ilang kaso ay remote code execution. Nakaupo ang flaw sa ilalim ng routing core ng FastAPI sa humigit-kumulang 325 milyong download bawat linggo at umaabot sa local-LLM serving stack — vLLM, LiteLLM, at mga MCP server na ang spec ay nag-aatas ng unauthenticated na OAuth discovery endpoints. Ang kombinasyong iyon ng malawakang deployment at malinis na pag-akyat ang eksaktong profile na nagtutulak ng pagtaas ng score pagkatapos ng disclosure habang naipapakita ang mga ruta ng pananamantala sa labas at naglalabas ang mga vendor na naglulunsad ng apektadong gateway ng sarili nilang advisory na higit sa konserbatibong inisyal na rating.


   In plain language: Isang bug sa code na pinapatakbo ang milyun-milyong AI server ay nakakuha ng mababang iskor ng panganib, ngunit sabi ng mga eksperto ay mas malala ito, kaya tataas ito.

### Inilalagay ng BadHost Starlette host-header flaw ang open-source LLM serving stack sa saklaw para sa authentication bypass

- Pinatatalas ng sariwang pagsusuri ngayong linggo ang lawak ng pinsala ng BadHost (CVE-2026-48710), isang host-header injection flaw sa Starlette ASGI framework — ang routing core sa ilalim ng FastAPI — na nagbibigay-daan sa isang umaatake na ganap na kontrolin ang path na pinupuntahan ng isang request sa pamamagitan ng pagpasok ng iisang karakter sa HTTP Host header, na tinatalo ang anumang path-based authentication middleware. Humihila ang Starlette ng humigit-kumulang 325 milyong download bawat linggo, at umaabot ang flaw nang direkta sa local-LLM serving stack: natuklasan ito ng German security firm na X41 D-Sec sa isang OSTIF-sponsored na audit ng vLLM, at sumasaklaw ang apektadong bahagi sa FastAPI, vLLM, LiteLLM, at mga MCP server — na ang spec ay nag-aatas ng unauthenticated na OAuth discovery endpoints, na nagbibigay sa mga umaatake ng maaasahang ruta ng pananamantala — kung saan iniuugnay ng mga mananaliksik ang primitive na ito sa authentication bypass, server-side request forgery, at sa ilang kaso ay remote code execution laban sa mga AI service na nasa mga internal na network nang walang proteksyon ng reverse-proxy, ayon sa [InfoQ - BadHost vulnerability exposes AI agents, evaluators, and LLM gateways](https://www.infoq.com/news/2026/06/badhost-ai-systems-vulnerability/). Inilabas ang pag-aayos sa Starlette 1.0.1 (inilabas Mayo 21, isang araw bago ang pampublikong disclosure), at ang praktikal na mitigation ay basahin ang request path mula sa ASGI scope sa halip na mula sa muling-itinayong URL sa anumang middleware na gumagawa ng desisyon sa seguridad; may libreng scanner na nakapaskil sa [BadHost - CVE-2026-48710 Starlette host-header auth bypass](https://badhost.org/). Ang itinakdang CVSS score nito ay 6.5, na ayon sa mga nagdi-disclose na mananaliksik ay maliit kumpara sa tunay na downstream na epekto dahil sa kung gaano kalinis na umaakyat ang iisang-karakter na primitive, ayon sa [OSTIF - Disclosing the BadHost vulnerability in Starlette](https://ostif.org/disclosing-the-badhost-vulnerability-in-starlette/). ### Inilipat ng GitHub Copilot ang bawat plan sa usage-based billing habang inihahanda ng Microsoft ang sarili nitong coding model

- Inilipat ng GitHub Copilot ang lahat ng plan sa usage-based billing noong Hunyo 1, na inaalis ang flat-rate na premium-request model: ang premium request units ay pinalitan ng GitHub AI Credits na ginagastos laban sa inilathalang per-model token rates para sa input, output, at cached tokens, at wala na ang dating fallback na nagbibigay-daan sa mga user na naubusan ng kanilang allowance na bumaba sa isang mas murang model at magpatuloy sa pagtatrabaho — pinamamahalaan na ngayon ang paggamit ng mga available na credit at ng admin budget controls, ayon sa [The GitHub Blog - GitHub Copilot is moving to usage-based billing](https://github.blog/news-insights/company-news/github-copilot-is-moving-to-usage-based-billing/). Nakaakit ang pagbabago ng tuloy-tuloy na pagtutol mula sa mga developer, kung saan nag-post ang mga user ng mga projection na 10x-hanggang-50x na pagtaas ng gastos — isa ang tumantya ng pagtalon mula $29 patungong $750 bawat buwan, isa pa mula $50 patungong $3,000 — habang inilalantad ng metered na model ang mabibigat na agentic workload sa per-token na gastos, ayon sa [Talakayan sa Komunidad ng GitHub - GitHub Copilot is moving to usage-based billing](https://github.com/orgs/community/discussions/192948). Dumadapo ang timing nang direkta laban sa Build keynote ng Microsoft kinaumagahan, kung saan inihahain ang in-house na MAI coding model bilang isang makina na may mas mababang inference-cost para sa Copilot — ang paglipat sa billing at ang mas murang first-party na model ay dalawang kalahati ng iisang kuwento ng margin.
