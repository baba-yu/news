1. Magkakaroon ang open-weight na text-diffusion LLMs ng pangalawang pamilya o edge runtime sa Q1 2027

   Ang paglabas ng Google ng DiffusionGemma sa ilalim ng Apache 2.0 noong June 10 ang sandaling tumigil ang open-weight na text diffusion bilang research curiosity at lumitaw bilang magagamit na local model. Isang 26B Mixture-of-Experts (3.8B active) na nakabatay sa Gemma 4 backbone na may idinagdag na diffusion head. Tumatalikod ito sa pakaliwa-pakanang autoregressive decoding para pinuhin ang isang 256-token na bloke nang sabay-sabay sa maraming pasada, ipinipirmi ang mga kumpiyansang token bilang konteksto para sa hanggang 4x na mas mabilis na pagbuo. Lumitaw ito na may native na suporta sa vLLM, Hugging Face Transformers, MLX, NVIDIA NeMo, at Unsloth, kasama ang isang inilabas na Unsloth Sudoku fine-tune na ginagamit ang bidirectional attention nito. Dalawang bagay ang gumagawa rito bilang binhi at hindi pang-isahang pangyayari. Una, tahasang sinasabi ng Google na nahuhuli ang kalidad ng output sa karaniwang autoregressive Gemma 4 at ibinabalik ang gawang pang-produksiyon sa autoregressive model, kaya ipinupwesto ang diffusion nang tahasan para sa local inference na mahalaga ang bilis at mababa ang concurrency. Ito mismo ang puwang na itinatayo ng isang edge runtime para punan. Pangalawa, hindi pa handa para rito ang on-device stack. Nakalista pa lamang bilang paparating ang suporta sa llama.cpp, kaya ang GGUF/CPU na daanan kung saan talagang naka-deploy nang lokal ang mga Gemma-class na weight ay hindi makakapagpatakbo ng block-parallel na diffusion decoding sa araw ng paglunsad, at iisa lamang ang miyembro ng open-weight na text-diffusion na larangan. Ang tesis pasulong ay tumitigas ang text diffusion bilang itinatag na kategorya ng open-weight na model sa halip na manatiling iisang Google checkpoint. Ang konkreto at masusubok na landing: pagsapit ng Q1 2027 ay MALAMANG isang pangalawa at independiyenteng malaking open-weight na text-diffusion language model ang lumitaw na may sariling model card at weight sa ilalim ng permissive o open na lisensya mula sa isang publisher na hindi Google (ang pinakamalalakas na kandidato ay ang Alibaba/Qwen, Meta, DeepSeek, Mistral, o NVIDIA), O isang mainstream na on-device inference runtime na hindi sumusuporta rito noong paglunsad ng DiffusionGemma - una sa lahat ang llama.cpp, o LM Studio, Ollama, o MLX bilang nakabalot na GGUF/edge na daanan - ang maglalabas ng first-class na block-parallel na text-diffusion decoding upang tumakbo ang format sa consumer CPU/edge stack. Hindi binibilang ang isang research-only na papel na walang inilabas na weight, isang pang-isahang Google follow-up checkpoint, o isang runtime na nagbabalot lamang sa umiiral na PyTorch na daanan nang walang native na diffusion-decoding na suporta. Ang marka ay isang pangalawa at independiyenteng paglabas ng open-weight na diffusion-LLM o tunay na edge-runtime na suporta para sa decoding scheme. Kung pagsapit ng March 31, 2027 ay ang DiffusionGemma pa rin ang tanging open-weight na text-diffusion model at walang mainstream na on-device runtime ang nagdagdag ng native na diffusion decoding, bumagsak ang hula.

2. Magiging pamantayang harness primitive ang matibay na ask-user checkpoint pagsapit ng H1 2027

   Ang datasette-agent 0.2a0 ni Simon Willison, na inilabas noong June 10, ay nagdaragdag ng kakayahang kulang pa sa karamihan ng autonomous-loop harness. Isang tool na nagdedeklara ng context parameter ang tumatanggap ng ToolContext object at maaaring tumawag ng await context.ask_user(...) para ihinto ang takbo at tanungin ang operator ng yes/no, multiple-choice, o free-text na tanong sa halip na manghula. Nananatili sa database ang suspended conversation at nakakaligtas sa restart ng server, kaya nagpapatuloy ang kalahating-tapos na takbo kapag sumagot na ang tao. Ang kapares na save_query tool ay nagsusulat ng SQL na binuo ng agent bilang naka-store na query pagkatapos lamang ng tahasang pag-apruba ng tao. Mahalaga ito dahil hindi ito isang UI confirmation popup kundi isang matibay na suspend/resume checkpoint na nakakaligtas sa restart, ipinatupad sa antas ng indibidwal na tool. Ito mismo ang human-in-the-loop primitive na tinatahak ng mga durable-execution na agent framework mula sa panig ng orkestrasyon. Habang lumilipat ang mga agent mula sa chat tungo sa pangmatagalan at walang-bantay na gawa, lumilipat ang failing mode mula sa maling sagot tungo sa maling di-mababawing aksyon na ginawa nang walang pagkakataong makialam. Ang matibay na sagot ay hayaan ang anumang tool na ihinto ang takbo, magtanong, at hawakan ang estado nito sa kabila ng pagkamatay ng proseso hanggang sumagot ang tao. Isang kontrol na hindi umiiral kung ang tanging checkpoint ay panandaliang in-memory na prompt na naglalaho kapag nag-restart. Ang tesis pasulong ay tumitigas ang ask-user-at-makaligtas-sa-restart na checkpoint mula sa iisang open-source na implementasyon tungo sa inaasahan at pinangalanang katangian ng mga malalaking agent harness at coding-agent runtime. Ang konkreto at masusubok na landing: pagsapit ng H1 2027 ay hindi bababa sa dalawang malalaking agent harness o coding-agent framework (ang pinakamalalakas na kandidato ay isang Claude Code / Codex CLI / Cursor / Cline-class na coding agent, isang orchestration framework gaya ng LangGraph o isang durable-execution runtime gaya ng Temporal o Restate, o isang managed agent platform gaya ng AWS Bedrock AgentCore o Microsoft Foundry) ang maglalabas ng dokumentadong human-input primitive sa kalagitnaan ng pagpapatupad kung saan ang isang tumatakbong tool ay makapaghihinto sa agent, makahihiling ng nakatipong sagot o pag-apruba mula sa operator, at makakapagpatuloy ng parehong takbo pagkatapos ng buong restart ng proseso o server. Naka-persist ang estado, hindi muling itinatanong mula sa wala. Hindi binibilang ang isang panandaliang in-memory na approval prompt, isang pre-run na permission allowlist, o isang after-the-fact na audit log. Ang marka ay isang dokumentadong suspend-ask-resume na checkpoint na matibay na nakakaligtas sa restart, inilabas ng isang stack na hindi Datasette.


   In plain language: Maaaring huminto ang isang open-source na AI agent, magtanong sa tao, at magpatuloy pagkatapos ng restart; kokopyahin ito ng malalaking agent tool.

Nagsisimula ito mula sa isang canvas ng mga placeholder token at pinipino ang isang 256-token na bloke nang sabay-sabay sa maraming pasada, ipinipirmi ang mga kumpiyansang token bilang konteksto at tinatapos ang mga 15-20 kada pasada, para sa hanggang 4x na mas mabilis na pagbuo kaysa sa katumbas na autoregressive baseline, ayon sa [Google - DiffusionGemma: 4x faster text generation](https://blog.google/innovation-and-ai/technology/developers-tools/diffusion-gemma-faster-text-generation/). Nakabatay ito sa Gemma 4 (26B-A4B) backbone na may idinagdag na diffusion head, sumusuporta sa 256K na konteksto sa mahigit 140 wika na may text/image/video na input, at umaabot sa 1,000+ token/sec sa isang H100 at 700+ sa isang consumer RTX 5090 sa mga 18GB VRAM kapag quantized. Ang gawa ay isang kolaborasyon ng Google DeepMind at NVIDIA na may native na suporta sa vLLM, Hugging Face Transformers, MLX, NVIDIA NeMo, at Unsloth, at deployment sa pamamagitan ng Google Cloud Model Garden at NVIDIA NIM, habang nakalista pa lamang bilang paparating ang suporta sa llama.cpp, ayon sa [MarkTechPost - Google AI releases DiffusionGemma, a 26B MoE open model using text diffusion](https://www.marktechpost.com/2026/06/10/google-ai-releases-diffusiongemma-a-26b-moe-open-model-using-text-diffusion-for-up-to-4x-faster-generation/). Tahasang inaamin ng Google ang trade-off. Sinasabi nitong mas mababa ang kalidad ng output ng DiffusionGemma kaysa sa karaniwang Gemma 4 at inirerekomenda ang autoregressive model para sa gawang pang-produksiyon, kaya inilalagay ang diffusion variant para sa local inference na mahalaga ang bilis at mababa ang concurrency sa halip na high-QPS na cloud serving. Kapansin-pansin, kasama sa paglunsad ang isang Unsloth-fine-tuned na variant na lumulutas ng Sudoku, na ginagamit ang bidirectional (hindi pakaliwa-pakanan) attention ng model para punan ang grid bilang isang constraint-satisfaction problem. Konkretong patunay ito na binabago ng diffusion formulation kung anong mga gawain ang magaling sa isang maliit na local model, hindi lang kung gaano ito kabilis tumakbo. ### May bagong pattern sa agent-tooling na lumitaw: mga agent na huminto sa kalagitnaan ng takbo para magtanong sa user, habang inilabas ni Simon Willison ang datasette-agent 0.2 na may ToolContext.ask_user primitive at matibay na mga suspended conversation na nakakaligtas sa restart

- Inilabas ni Simon Willison ang datasette-agent 0.2a0 noong June 10, na nagdaragdag ng kakayahang matagal nang wala sa karamihan ng mga autonomous-loop harness: maaari na ngayong ihinto ng isang tool ang takbo ng agent para magtanong sa operator sa halip na manghula. Ang mga tool na nagdedeklara ng context parameter ay tumatanggap ng ToolContext object at maaaring tumawag ng await context.ask_user(...) para sa yes/no, multiple-choice, o free-text na input. Ang mahalaga, ang suspended conversation ay nananatili sa database at nakakaligtas sa restart ng server. Nagpapatuloy ang kalahating-tapos na takbo ng agent mula sa kung saan ito huminto kapag sumagot na ang tao. Nagdaragdag din ang release ng isang save_query tool na nagsusulat ng SQL na binuo ng agent bilang naka-store na Datasette query pagkatapos lamang ng tahasang pag-apruba ng tao, ayon sa [Simon Willison - datasette-agent 0.2a0](https://simonwillison.net/2026/Jun/10/datasette-agent/). Isang araw bago nito, inilabas ni Willison ang llm 0.32a3, ang pinakabagong alpha ng kanyang command-line LLM toolkit, na binabanggit niyang halos buong-buong isinulat ng kabago-lang-inilunsad na Claude Fable 5 ng Anthropic, ayon sa [Simon Willison - llm 0.32a3](https://simonwillison.net/2026/Jun/9/llm/). Pinagsama-sama, isang maliit ngunit may-tudla na senyales ang mga ito sa antas ng agent-workflow. Sa halip na itulak ang mga agent tungo sa ganap na walang-bantay na takbo, gumagalaw ang disenyo tungo sa mga human-in-the-loop na checkpoint bilang first-class at matibay na primitive. Mga gate ng paglilinaw at pag-apruba sa kalagitnaan ng pagpapatupad na humahawak sa estado sa kabila ng mga restart ng proseso. Ito mismo ang pangangailangang matagal nang itinatayo ng mga durable-execution na agent framework, ngunit dito ipinatupad sa antas ng indibidwal na tool sa isang open-source stack. [Simon Willison - datasette-agent 0.2a0](https://simonwillison.net/2026/Jun/10/datasette-agent/), [Simon Willison - llm 0.32a3](https://simonwillison.net/2026/Jun/9/llm/)
