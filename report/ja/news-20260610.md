### CISA、実際に悪用されている LiteLLM の MCP コマンドインジェクションの欠陥を KEV カタログに追加。エージェントスタックのツール配線層が、実環境で確認された認証情報窃取の経路に変わった

- Model Context Protocol を中心としてきたエージェントセキュリティの露出が、6月9日に研究段階から悪用確認の段階へと移った。この日、CISA は CVE-2026-42271（LiteLLM の MCP サーバープレビュー用エンドポイントにあるコマンドインジェクションの欠陥）を、悪用が確認された脆弱性（Known Exploited Vulnerabilities）カタログに追加した。この欠陥は、認証のない2つのテスト用エンドポイント（POST /mcp-rest/test/connection と /mcp-rest/test/tools/list）に存在する。これらは command・args・env フィールドを含むサーバー設定一式をリクエスト本文で受け取り、検証なしにプロキシホスト上のサブプロセスとして起動するため、攻撃者は LiteLLM プロキシとしてのコード実行を得る。さらに Starlette のホストヘッダーバイパスである CVE-2026-48710 と連鎖させると、ログインもAPIキーも事前アクセスも不要な CVSS 10.0 の認証なしリモートコード実行に至る（[CybelAngel - LiteLLM vulnerability CVE-2026-42271: 7 things to know](https://cybelangel.com/blog/itellm-vulnerability-cve-2026-42271/)）。LiteLLM は数百のモデルプロバイダーへの呼び出しを仲介するオープンソースのプロキシだ。そのため、ここに侵入した攻撃者は、接続されたすべてのAIサービスのプロバイダー認証情報とAPIキーを読み取り、組織の残りの推論インフラへと横展開できる。欠陥は4月20日に公表され、5月8日にバージョン1.83.7で修正された(1.74.2から1.83.6が影響を受け、Starlette は1.0.1で修正)。だが KEV への登録は、Horizon3.ai が6月1日に連鎖RCEの実働エクスプロイトを確認したことを受けたものだった。CISA は実環境での攻撃が進行中だと警告し、連邦政府向けの修正期限を設定した（[Help Net Security - LiteLLM vulnerability under active attack, CISA warns (CVE-2026-42271)](https://www.helpnetsecurity.com/2026/06/09/litellm-vulnerability-under-active-attack-cisa-warns-cve-2026-42271/)）。この一連の流れは、エージェント型AIに対するゼロトラストの方針を裏づける。エージェントをツールに配線するプロキシと MCP 設定の層そのものが、認証のない、インターネットから到達可能な攻撃対象領域なのだ。KEV の期限に沿って修正し、公開インターネットから切り離し、配管ではなく価値の高い認証情報の保管庫として扱わなければならない。 [CybelAngel - LiteLLM vulnerability CVE-2026-42271: 7 things to know](https://cybelangel.com/blog/itellm-vulnerability-cve-2026-42271/), [Help Net Security - LiteLLM vulnerability under active attack, CISA warns (CVE-2026-42271)](https://www.helpnetsecurity.com/2026/06/09/litellm-vulnerability-under-active-attack-cisa-warns-cve-2026-42271/)
