1. カスタムAIアクセラレータのXPUシリコンが2026年第4四半期までに四半期あたり$20Bの年率換算収益を突破する

   カスタムAIアクセラレータ向けシリコン、すなわちBroadcomとその同業他社が汎用GPUの代替として製造する、ハイパースケーラー設計のXPUおよびASICは、2026暦年の終わりまでにBroadcom単体で四半期あたりおよそ$20Bの収益の年率換算ペースを突破する軌道にある。あわせて、名前の挙がる中核的なカスタムシリコン顧客の数が6社を超えることも開示される見通しだ。Broadcomの会計年度第2四半期の決算がその引き金である。AI半導体収益は$10.8Bで前年同期比143%増、第3四半期は200%超の成長率で約$16Bと見通され、AI半導体の受注は単一四半期で$30Bを超え、実際に出荷された$10.8Bを大きく上回った。現在の出荷量のおよそ3倍を前もって積んだ受注残は、緩やかに減衰していく需要の引き合いではない。それは既に売れてしまった生産能力であり、出荷収益の数字は受注の数字から遠ざかるのではなく、そこへ向かって登っていく傾向がある。第3四半期が見通しどおり$16B近辺に着地すれば、四半期ごとの傾きと開示された受注残により、その次の四半期は$20Bの大台に手が届く。同じ力学が顧客構成にも圧力をかける。6社の中核XPU顧客で四半期に$30Bを受注できたのであり、単一のハイパースケーラーによるカスタムシリコンプログラムの経済性、つまり設計コストを社内に抱える推論・学習需要に対して償却していく構図は、いまや目に見えて有利だ。そのため、開発段階から量産へと卒業していく新たな名前付きプログラムが増えることは、最も抵抗の少ない自然な流れとなる。したがって注視すべき将来の状態は、収益の閾値と顧客構成の拡大の両方であり、いずれか一方が確認されれば、カスタムASICの系統がもはやGPU配分に対するニッチな保険ではなく、アクセラレータ計算資源の構造的に積み上がる第二の供給ラインになったことを裏付ける。


   In plain language: 自社のAIチップを設計する企業は、前四半期に買った量のおよそ3倍を既に発注しているため、それらのチップはまもなく桁違いに多く売れる。

3. 統制されたエージェント・オントロジー層が2026年第4四半期までに企業向けエージェントの堀として固まる

   生の倉庫データと、それに問い合わせるエージェントの間に位置する、統制されたセマンティック/オントロジー層が、企業向けAIにおける争いの中心になりつつある。そして2026年第4四半期までに、2社目の主要データプラットフォームが、直接比較できる統制されたエージェント向け文脈の提供層を出し、特定の単一ベンダーではなくカテゴリそのものを裏付ける。Snowflake Summitのビルダーキーノートはその形を明確に示した。Cortex Senseが、Horizon Contextという統制層の上にメタデータからオントロジーへの層を自動構築し、エージェントがスキルとセマンティクスの共有された単一の定義を利用できるようにする。これはBlackRockが自社のエージェントを、企業の真実を表すHorizon Contextの単一の定義に基づいて動かす実演と、Sanofiのエージェント「Concierge」がライブデータから営業担当者の準備を整える実演で示された。これが機能ではなく堀である理由は、エージェントは自らが読み取るセマンティック層・統制層の信頼性を超えては信頼できないからだ。その層を所有する者が、上にどのモデルが載るかに関わらず、企業向けエージェントがどこで動くかを握る。同じ基調講演は、Polarisの双方向書き込みを備えたIceberg v3をGAに引き上げることで、オープンなテーブル形式を当然の前提へと押し進めた。これによりSparkやTrinoといった外部エンジンが重複なしに統制されたテーブルへ書き込めるようになり、ロックインが差別化要因ではなくなり、争いを統制とオントロジーの層へと押し上げる。6月15〜18日のDatabricks Data + AI Summitは、統制とエージェントの専用トラックを備えており、Unity Catalogに紐付いた同等のエージェント向け文脈/オントロジーの発表が近い将来になされる最有力の場である。さらに年末までには、少なくとももう1つのプラットフォーム、またはカタログをエージェントが利用可能なセマンティック層へ拡張するオープン標準の提案からも、追加の圧力がかかるはずだ。


   In plain language: 信頼でき統制された会社データの地図を所有する者がAIエージェントの動く場所を握るため、競合するデータクラウドもその地図を作ろうと競い合う。

### Unsloth Studioの6月版ビルドが、ローカルのファインチューニングUIをMCPに接続したエージェントの作業台に変える

- Unslothは今週、新版のStudioビルドを公開し、ローカルのファインチューニングUIを学習とチャットの域から大きく押し進めて、MCPに接続したエージェントの領域へと踏み込んだ。目玉となる追加機能は組み込みのModel Context Protocolサポートである。StudioはContext7、Exa、Hugging FaceのMCPサーバーを既定で有効にして同梱し、Gemma 4やQwen3.6といったローカルで動かすモデルが1つのチャットスレッド内でこれらのツールを自律的に呼び出せるようにし、さらにOAuthまたはトークン認証と自動ツール検出を用いて任意のカスタムMCPサーバーをURLで追加する流れも用意した（[Unsloth Documentation - How to Use MCP Servers with Local LLMs](https://unsloth.ai/docs/basics/mcp)による）。同じビルドはData Recipesも追加した。これはNVIDIA Nemo Data Designerを基盤とするグラフベースのデータセット作成エディタで、PDFやCSVを取り込み、シードデータと生成ブロックを接続し、サンプル出力をプレビューし、Studioのファインチューニングへ直接流れ込む合成データセットの生成を一通り実行できる（[Unsloth Documentation - Unsloth Data Recipes](https://unsloth.ai/docs/new/studio/data-recipe)による）。MCP、Projects、Canvas、刷新されたチャットUIの作業とあわせて、このリリースは、前週のCUDA 13.3のWindowsバイナリとApple Siliconでのllama.cpp再有効化から続くUnslothのハードウェア対応拡大を、Linux上のNVIDIA BlackwellとB300にまで広げ、256Kトークンの文脈長を持つGemma 4 12Bを、民生クラスのメモリで実行・学習可能な対象として組み込んだ。通底するのは、小型のオープンモデルをQLoRAでファインチューニングするのに使う同じツールが、いまや、ツールを使うローカルエージェントのクライアントと合成データ生成基盤を兼ね、開発者が既に所有しているハードウェア上で、ファインチューニングとエージェントの出荷の隔たりを狭めているという点だ。 [Unsloth Documentation - How to Use MCP Servers with Local LLMs](https://unsloth.ai/docs/basics/mcp), [Unsloth Documentation - Unsloth Data Recipes](https://unsloth.ai/docs/new/studio/data-recipe)
