   QiAnXin の XLab は NadMesh を、自前で運用されている AI の基盤をポート単位で列挙するスキャナとして描いている。ComfyUI、Ollama、n8n、Open WebUI、Langflow、Gradio を、8188、11434、7860、5678 の各ポートにわたって当たり、持ち去るのは計算資源ではなく認証情報だ。環境変数からのクラウドの鍵、Kubernetes のサービスアカウントのトークン、そして ~/.aws/config と .env の中身である。XLab は運用者自身の集計を露骨に疑ってかかっているが、標的の一覧のほうは、それとは関係なく成り立つ。この出来事を構造の話にしているのは、AI の一式が最初の侵入口の内訳のなかで、いまどんな面々と並んでいるかである。Docker API を介した遠隔でのコード実行が30.31%、Jenkins のスクリプトコンソールでの実行が22.28%、telnet の弱いパスワードが10.36%、Redis が8.29%。これは設定ミスの定番の顔ぶれであり、なかでも Redis がいることが効いてくる。Redis はすでに、ここで予測する矯正を一度くぐっているからだ。開いたインスタンスへの大量のスキャンが protected mode を生み、パスワードが設定されていないときには遠隔のクライアントに応じないようになった。MongoDB は自らの身代金要求の波の後、待ち受けのアドレスをループバックへ移した。Elasticsearch は、外部へ経路の通るアドレスに待ち受けた時点で、本番向けの検査を必須にした。AI のツール群は、この周回をまだ経ていない。いくつかはすでにループバックに待ち受けているが、どれにおいても、認証情報が公開の度合いを決めてはいない。フラグか環境変数を1つ与えればサービスはネットワークに出ていき、何かが認証されるかどうかは、誰も触る義務のない別の設定なのだ。だからこそ、いま出回っている助言は、ソフトウェアによる強制ではなく境界の衛生管理にとどまっている。予測は、そのソフトウェアのほうが強制を始める、というものだ。H1 2027 までに、ComfyUI、Ollama、Open WebUI、Langflow、n8n、Gradio のうち少なくとも2つが、認証情報のないままループバック以外のインターフェースに待ち受けようとする操作を、拒む、ループバックへ差し戻す、あるいは明示的な了解の後ろに置く——そういうリリースを出す。しかもそれは、任意の堅牢化の手引きとしてではなく、リリースノートに互換性を壊す既定値の変更として記される形でだ。日程を決めるのは商業の側面である。いまやこれらのプロジェクトの背後には、資金を得た企業や、企業が所有する製品が座っている。ボットネットの標的の一覧に名指しで載ることは、サポートフォーラムのやりとりではなく、調達の段階での反対理由になる。締めくくるのは、XLab が記録した破綻の筋道だ。長く生き続けるクラウドの認証情報のファイルの隣でローカル推論を動かしているワークステーションは、そのファイルが持つアカウントへ横方向に入り込むための経路である。そして、堅牢化の手引きを一度も読まない運用者に届く制御は、出荷時の既定値だけなのだ。


   In plain language: ボットネットが、家庭の AI サーバーからクラウドのパスワードを探して回っている。だから近いうちに、これらのツールはログインなしで外に出ることを拒むようになる。
