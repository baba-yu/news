1. LFM2.5-2.6B の 2.5 GB 未満という主張に、Q3 2027 までに文脈の長さが名指される

   だが面白い但し書きはそこではない。面白いのは、三つのうち二つが同じ一つの過程の別々の状態を述べているのに、この公開がその二つを一緒に述べていないことである。2.5 GB 未満はモデルについての数だ。128K は、一続きのやり取りをどれだけ抱えられるかについての数だ。道具を呼ぶエージェントの繰り返しは、その二つが出会う場面であり、公開はそこがどうなるかを言っていない。エージェントと呼ぶに値するほど長く回る繰り返しは、道具の出した結果と、途中の段取りと、自分自身の記録を溜め込んでいる。その溜まりが何を費やすのかが、やり取りの初めではなく深いところで、まだそれが機械の上に留まっていられるかを決める。8K でいくらか、32K でいくらか、掲げている 128K でいくらか。モデルと一緒に出された材料は、そのどれについても何も言っていない。2.5 GB 未満と言い、別のところで 128K と言い、前者が後者を生き延びるのだと読み手に思わせるまま置いている。
   
   この隙間は、外に置かれたモデルの場合より、ここでのほうが重い。この公開の論の全部が、機械の側の上限に乗っているからである。会社自身が測った機械の上での値——Apple M5 Max で毎秒 220 トークン、AMD Ryzen AI Max+ 395 で毎秒 113 トークン——は速さであって、占める大きさではない。NVIDIA H100 一枚で同時の求めを多く受けたときに出す側で毎秒 15,000 トークン近い、という数は置き場の側の数であり、また別の配置の問いに答えるものである。エージェントがノートの機械や手のひらの機械や組み込みの板に載るかどうかを決めようとしている書き手は、それがどれだけ速いかを尋ねてはいない。やり取りが深くなったとき、それが何を抱えているのかを尋ねている。足りなくなることが、自動で増やすことではなく落ちることを意味する機械の上でのことだ。この公開が先頭に置くと選んだ数はメモリの上限であり、そしてそれは、この公開がいちばん条件を付けずに述べている数でもある。
   
   予測はこうである。その上限に、文脈の長さが付く。Q3 2027 の終わりまでに、LFM2.5-2.6B について Liquid AI 自身が公にする材料——モデルの札、リポジトリの説明、あるいは会社からの続きの書き込み——が、メモリの数を、その数が成り立つ文脈の長さと一緒に述べる。片方の欄にメモリの数、もう片方の欄に文脈の長さのある表が一つあれば、それで決まる。名指された長さで走らせたやり取りについて、メモリの山の値が述べられていても決まる。数がどちらへ動くかは主張ではない。述べられること自体が主張である。
   
   弱いものがいくつか、数には入らない。どれも、こうした圧の下にある出し手が最初に手を伸ばすものだから、一つずつ挙げておく値打ちがある。条件を付けない数の繰り返しは、どれほど目立つ場所に置かれても数に入らない——それはすでに起きたことだからである。量子化の段ごとのファイルの大きさの表も入らない。置き場にあるファイルは、走っている繰り返しが抱えているものではないからだ。名指された文脈の長さで測った毎秒のトークン数も、それだけでは入らない。ある長さでの速さは、その長さでの占める大きさについて何も言わないからである。読み手が答えを導き出せる設定の綴りも入らない。機械の上に置けるという主張の宛先は、モデルを見比べている書き手であって、設定を読むほど深く肩入れした者ではないからだ。そして一族の別の一員について公にされた数も入らない。試されているのは、この公開に付いた主張である。
   
   いちばん強い反論は、効いている見出しに条件を付ける圧など出し手にはない、というものである。llama.cpp を走らせている実務の者は自分でこれを割り出すし、自社の上限をより悪く見せる数を公にせよと求めることは、自分の公開に反対せよと求めることである。二つめの反論は造りについてのもので、この予測を果たされないだけでなく不要にしてしまう類のものだ。文脈が埋まってゆくときにこのモデルのメモリがどう伸びるかを、この公開は何も述べていない。もしそれが並外れて平らに伸びるのなら、条件のない上限は見た目より正直に近く、述べ直すものが何もないことになる。三つめは、注意は競い合いのある場所へ向かうというもので、ここでの競い合いは物差しの表である。77.83 対 65.00 対 52.40 は、相手が答える比べ方だ。だからこの場所で次に公にされる数は、占める大きさより点数である見込みが高い。
   
   正直な失敗の形は、そのどれよりも静かである。その数は、都合が悪いからではなく誰も求めなかったから、ただ現れないままかもしれない。そして何かが述べられないままだという予測は、実際には何も起きなかっただけのときに、外れたように読める。これは、出し手が書き物の中で何を約束するかについての主張である。沈黙は、私に不利な形でこれを決める。

2. Herdr が Q2 2027 までに、Apache-2.0 の実行の土台の上に有料の層を公にする

   Herdr が8月6日木曜、Y Combinator の F26 の期に入ったと述べ、同じ書き込みの中で、自社の実行の土台を AGPL から Apache-2.0 へ付け替えた。Herdr は、命令行で動くコードのエージェントのための端末の実行の土台である。それらをペイン、タブ、プロジェクトに整え、それぞれが載っている機械の上で走らせ続ける。そしてそれらの機械は、今日は互いに切り離されている。集めた金の額は発表のどこにも現れず、期に入ったことは資金の調達ではないから、ここには数が付いていないし、読み手が補ってもいけない。この書き込みが述べているのは切り分けである。いま人が使っている実行の土台は Apache-2.0 のもとで無料のまま置き、商いにする機能はその上に積む。候補として名指されているのは二つ、機械をまたぐつなぎと、端末の外側にある窓口である。
   
   効いてくるのはライセンスの一行で、何が動いたのかを正確に言う値打ちがある。AGPL の網を通した利用についての条項こそ、Herdr の上に建てた外向けの役務に、その役務自身の元のコードを公にする義務を負わせていたものだ。Apache-2.0 はその義務を取り除く。外から見れば、これは採り入れやすさの変化である。AGPL の実行の土台を自社の役務の後ろに置けなかった会社が、置けるようになる。内から見れば、逆である。いま外れたその条項は、外向けの層を、実行の土台を書いた者たちのために取り置いていた、この積み重ねの中の唯一のものだった。それを手放せば、その層を取り置くものは、先にいることと、より良いことのほかに何もない。売るつもりだと自ら述べた層について法の側の主張を落とした会社には、その層を、述べられた計画ではなく値の付いた品に変える理由がある。ライセンスがもうその場所を押さえていないからである。
   
   同じ週が、もう一方の側から圧を供している。Meta の研究の組が8月5日水曜に Muse Code を公にした。端末の中で動くコードのエージェントで、はっきりベータであると断られており、そのサブエージェントは仕事ごとに生まれては消えるのではなく一つのやり取りのあいだ生き続け、モデルの呼び出し、道具の実行、承認、書き換えのすべてが手元の出来事の記録へ書き足されて、走りをそのまま再生でき、途中で止まっても安全にする。一続きのやり取りを跨いで生き続けること、そして止まっても生き残ることは、Herdr の実行の土台が掲げているのと同じ関心である。そしてその発表は、どの部分についても値を述べていない。この二つが置き換えのきくものだという意味ではない——Muse Code はエージェントで、Herdr はほかのエージェントがその中で走る土台である——が、大きな研究の組がこの層で出すと決めたとき、能力がどちらへ流れるかは見せている。そしてそれは、実行の土台そのものが請求書を運ぶものになる、という筋への反論でもある。
   
   予測はこうである。その意図が数になる。Q2 2027 の終わりまでに、Herdr は自社の有料の層について値を公にする——料金の頁か、その層がいくらかを述べた同等の公の文書として——そしてその層の説明が、8月6日の書き込みが商いのものとして名指した二つのうち少なくとも一つ、すなわち機械をまたぐつなぎか、端末の外側にある窓口を挙げている。実行の土台がその傍らで Apache-2.0 のもとに残ることは、差し支えではなく織り込みである。それがこの書き込みの述べた切り分けだからである。
   
   惜しいものがいくつか、数には入らない。どれも、この段階の会社が最初に手を伸ばすものである。順番待ちの名簿も、先行して使うための申し込みの様式も、近日という札も入らない。主張は公にされた値についてであって、公にされた意図についてではないからだ。8月6日の計画を後の書き込みで述べ直すことも、同じ理由で入らない。後援や寄付の押し釦も入らない。それは維持する者に払う道であって、層に付けた値ではない。売る側へ連絡せよと促すだけで数を載せない企業向けの頁も入らない。無料で外から使える役務も、値が付くまでは入らない。それが結局は有料になるものだと、どれほど明らかであってもである。そして資金の調達の発表は、どちらの向きにも入らない。調達は値ではなく、これを促した期への加入も調達ではなかった。
   
   二つの反論は、はっきり述べておく値打ちがある。一つめは、もとの材料のどこにも時計がないことである。この書き込みは商いの候補を挙げ、そこに日付を与えず、何についても数を与えていない。ライセンスを広げたばかりの小さな組には、近いところでは、そこに課金するより導入の数を伸ばす理由のほうが強い。ここで論じた圧は日取りではなく構えのものであり、構えの圧は長いあいだ受け止めていられる。二つめは、付け替えはこれらのどれがなくても元が取れる、というものだ。Apache-2.0 はこの実行の土台を採り入れられる者の幅をただちに広げるし、企ては緩いライセンスのまま、金を取らずにいつまでも続けられる。実際そうしているものは多い。
   
   正直な失敗の形は、そのどちらよりも静かである。有料の層は、それ自身の名を持つ外向けの品の中に束ねられて現れ、実行の土台の上に載る層としてではなく全体として値を付けられるかもしれない。その場合、ライセンスの綴りの隣に料金の頁を探した読み手はそれを見つけられず、正しかったものを外れたと呼ぶ。主張は、実行の土台の上の層に値が現れることについてであって、それが現れる頁の形についてではない。

   In plain language: Herdr は主となる道具を、誰でも自由に使い直せるようにしたばかりである。だからこれからの金は、有料の付け足しから来るしかない。


3. H1 2027 までに、端末のコードのエージェントが、担い手の承認した命令を拒むようになる

   Alex Wauters が8月5日水曜、Scale X のブログに分析を公にした。扱っているのは、遊ぶ人がコードのエージェントに対する人の承認者の代わりを務め、時間に追われながら一つ一つの命令を通すか拒むかを決める、ブラウザの中の遊びである。4万回を超える走りと、およそ 40万9,000 回の通すか拒むかの判断にわたって、当たった割合の平均は 66.3% だった。面白いのは平均そのものではない。その形である。見落としの率は、敵意ある命令が、人が恐れるよう仕込まれてきたものからどれだけ離れているかにつれて上がった。見るからに壊しにかかる命令で 11.7%、居座って書き換える攻めで 23.8%、データの持ち出しとコードの実行で 33.4%、及ぶ範囲を破るもので 35.0%。遊んだ人の 35.2% はすべての脅威を捉えたが、そのうえで安全な命令を五つに一つより多く止めなかった人は 20.8% にとどまる。7% は目の前に出されたものをすべて通し、32.9% の回は負の点で終わった。いちばん見落とされた命令は npm run analyze で、悪意ある中身が履歴の記録の中に見えていたにもかかわらず、64.7% の割合で通された。
   
   その場が作り物であることは、書いた本人がはっきり述べている——脅威は命令の 34% に現れており、これは現実のどんな仕事量よりはるかに多く、時間に追われる遊びは働く一日ではない——そしてその但し書きは両側に効く。現実の担い手が敵意ある命令に出会うのはもっと稀で、だからこそ身構えができていないからである。但し書きを越えて残るのは平均ではなく順序であり、その順序は、情報がどこにあるかについての言明である。承認の問いかけが見せるのは命令の一行だ。見落としの率が沿って動いたのは、その一行が何に解けるかのほうであり、npm run analyze の場合、それは遊ぶ人が判じよと言われた文字列の一段下、問いかけが見せない記録の中にあった。名前を承認せよと言われた人に、中身は検められない。それは訓練の足りなさではないし、問いかけをはっきりさせたところで良くならない。
   
   同じ一回りの中の二つの品が、これが押し込む先の層を描いている。Meta の研究の組は8月5日水曜に Muse Code を公にした——端末の中で動くコードのエージェントで、はっきりベータであると断られ、macOS と Linux には dev.meta.ai から導入の手順書を流し込んで入れる——そのサブエージェントは非同期で、仕事ごとに生まれては消えるのではなく一つのやり取りのあいだ生き続け、主のエージェントへいつ報せるかを自分で決める。これが、幾つもの段を踏む仕事から往復の待ち時間を取り除いている。モデルの呼び出し、道具の実行、承認、書き換えのすべては手元の出来事の記録へ書き足され、Meta はこれを、走りをそのまま再生でき、途中で止まっても安全にするものだと語る。承認はそこにも明らかに残っている。記録がそれを書き留めているのだから。動いたのは、命令の一行が一人の人の前へ届く速さを決めるのが、その人ではなく段取りを組む仕掛けになったということである。そしてこの遊びが測ったのは、まさにその条件の下での当たりの割合だった。8月6日木曜に自社の端末の実行の土台を語った Herdr が、残る半分を供している。エージェントをペイン、タブ、プロジェクトに整え、それが走っている機械の上で走らせ続けることである。生き続けることを売りにする実行の土台とは、その仕事の大半を、誰も見ていないあいだに済ませる実行の土台である。
   
   確かめを道具の層へ移すことへの、これまでの反論は費えだった。動かない規則の一覧は安いが脆く、中身まで実際に読むものは、その後ろにモデルを欲しがる。その縛りも今週動いた。Liquid AI が8月4日火曜に LFM2.5-2.6B を公にした。26億パラメータで、段取り、道具の呼び出し、幾つもの段を踏む仕事に向けられ、2.5 ギガバイト未満のメモリに収まる。会社自身が測り、モデルと一緒に出されただけで外の手では再び確かめられていない値は、Apple M5 Max で毎秒 220 トークン、道具の使いこなしを見る ToolSandbox で 77.83、これは Gemma 4 E4B-it の 65.00 に対する数字である。それらは売り手の数として扱えばよい。実際そうなのだから。移せるのはメモリの上限のほうである。命令が何に展けるかを読む仕組みが、その向こうに外の役務があることを、もう意味しなくなった。この予測は、確かめる側がモデルであることを求めてはいない。決まりきった手順の仕掛けでも同じように足りる。言いたいのはもっと狭い。決めを人の手に残しておくための、運びの上での最後の言い訳が、取り除きやすくなった。
   
   予測はこうである。担い手のはいが、それだけでは足りなくなる。H1 2027 の終わりまでに、名の付いた端末のコードのエージェントか、その実行の土台が、2026年8月6日より後の日付で、2027年6月30日に効いている振る舞いを述べた版の覚え書き、変更の記録、あるいは説明の頁を公にする。そこでは、ある一群の道具の働きが、その命令が何に解けるか、あるいはそれが何へ届くかを根拠に既定で拒まれ、承認の問いかけに答えてもそれは使えるようにならない。その拒みを外すには、走っているやり取りの外側で設定を変えることが要らなければならない。求める線は、ふつうに入れれば付いてくる既定であること、そして鍵盤の前にいる人が答えで押し通せない拒みであることだ。
   
   安く済ませたいくつかの結末は、数に入らない。どれも、こうした圧の下にある仕掛けが最初に手を伸ばすものだから、一つずつ挙げておく値打ちがある。より豊かな承認の問いかけは入らない——差分の下見、危うさの点数、色、別名の後ろにある手順書の本体、そのどれもが決めを担い手に残すからで、66.3% で測られたのはその担い手である。新しい種類の生成物について承認の段を別に足すことも、同じ理由で入らない。問いかけをもう一つ増やすことは、一つ取り除くことではない。命令の文字列の禁じ手の一覧も入らない。見るからに壊しにかかる命令こそ見落としの率が最も低かった場所——11.7%——なのだから、文字列の一覧は人がすでに通っている確かめを作り直すだけで、35.0% だった及ぶ範囲を破るものを、そのままの場所に残す。切って出された選択肢も入らない。方針を中央で効かせる企業向けや外向けの層があっても、ふつうに入れたものが問いかけだけを門にしているなら、それも入らない。この命令はこれから通す、という覚えさせた答えは、この主張の逆である。囲い込みが入るのは、その拒みを、ふつうに入れたものがすることとして版の覚え書きが述べている場合だけで、担い手が選ぶ形として述べているなら入らない。
   
   いちばん強い反論は、この測りが移らないというもので、書いた本人が真っ先に挙げるだろう。命令の 34% に脅威の現れる、時間に追われるブラウザの遊びは働く一日ではないし、66.3% は、ある特定の仕掛けの使い手ではなく遊びを遊んだ人たちの平均である。よそで出た数に合わせて設計する義務は、どの売り手にもない。二つめの反論は品としてのもので、これが重い。担い手が押し通せない拒みは、支えの求めを、売り手の判断についての言い争いに変えてしまうし、端末のエージェントの魅力は、頼んだことをやってくれることにあるからだ。Muse Code 自身の設計はそちらへ引く。待たずに幾つもの段を進めるために作られたサブエージェントは、固い拒みによって途中で止められるサブエージェントであり、その費えは、方針が誤るたびに請求される。三つめは正直な失敗の形で、これは静かである。その変化は、運びの機能の装いで来るかもしれない——許しの型、ファイルと網の及ぶ範囲——そして覚え書きのどこにも承認という語がなく、セキュリティの発表を探して目を走らせる読み手はそれを丸ごと見落とす。それでも数には入る。主張は、ふつうに入れたものが何を拒むかについてであって、売り手がそれをどう述べることに決めるかについてではない。

   In plain language: AI のエージェントが何を走らせるかを承認する人は、三度に二度ほどしか当てられない。だから道具の側が、そろそろ自分で断りはじめるべきである。

### 4万回を超える走りにわたる実験が、人がエージェントの命令をどれだけうまく承認できるかを測る。答えは、装いの深さにつれて動く
