## Future


1. Hugging Face の取り寄せの仕組みは、Q2 2027 までに XET から HTTP への既定の退避を出さない

   Alibaba は 8月3日月曜に Qwen3.8-Max を一般提供にした。全体で 2.4 兆パラメータ、トークンあたりで働くのがおよそ 950 億で、重みは来週、小さいほうの Qwen3.8-27B と並べて公開すると言っている。同じ日に Unsloth は 2026.8.2 を PyPI に公表した。2026.8.1 の一つあとの版であり、その中身はカーネルでもなければ新しいモデルの系統でもなかった。ダウンロードはいま、XET が詰まったときに自動で普通の HTTP へ退く。XET とは、大きな置き場に対して素のファイルの取り出しの代わりにHugging Face が使う転送の経路のことだ。転送に使う記憶も大きく減った。公表の記録は一行である。「Unsloth now auto fallbacks to HTTP if XET stalls.」学習を小さいハードウェアに収めることを存在の理由とする計画が、一回ぶんの公表を、ダウンロードを終わらせることに使った。
   
   この予測は、その直しがどこまでは行かないか、についてのものである。Q2 2027 の終わりまで、huggingface_hub の既定の取り寄せの経路は、詰まった XET の転送を、同じファイルを素の HTTP で終わらせることによって立て直したりはしない。立て直しの仕事は XET の内側に留まる——やり直しを増やし、詰まりの見つけ方をよくし、塊ごとの再開を入れ、配る仕組みを速くする——そして、経路をまたぐ逃げ道は、Unsloth が置いた場所、つまりファイルを受け取る側の計画に留まる。
   
   今日、この読み手の側にそんなものはなく、その理由はコードの形が語っている。取り寄せの経路は、一バイトも動かないうちに一度だけ決める。置き場が XET に支えられていて hf_xet の一式が入っていれば XET の取り出しを呼び、そうでなければHTTP の取り出しを呼ぶ。そして両者の間に、ファイルを飛んでいる途中で前者から後者へ移せるような取り扱いは置かれていない。この経路が fallback という語を使う唯一の場所は、hf_xet がそもそも入れられたことのない機械に向けた警告だ——置き場では XET が有効なのに一式が欠けているので、普通の HTTP のダウンロードに退いている、というものである。これは速い経路を一度も持たなかった読み手のための退避であって、速い経路を失った転送のための退避ではない。HF_HUB_DISABLE_XET も同じ限界を言い表している。どちらの経路が選ばれるかを変えるだけで、選ばれた経路が死んだときに何が起きるかは変えない。
   
   この仕組みが守るはずの失敗は、絵空事ではない。huggingface_hub 自身の報告の場に開いたままの報告が二つ、そう言っている。7月11日に出された Issue #4520 では、大きな取り出しの途中で進み具合の表示と XET の記録がただ更新されなくなる。6月12日に出された Issue #4349 が、退避を口で言うほど簡単にはしない細部だ。XET をすでに無効にしていても、素の HTTP の経路にはそれ自身のやり直しがなく、42.5 ギガバイトのうち 17.3 で死に、再開のもとになるものが控えにも何も残らない。逃げ道が、そこから逃げる相手より明らかに信頼できる、というわけではないのである。
   
   直しを XET の内側に押しとどめている力は、XET が転送の細部ではなく製品そのものだということだ。まさにこうした置き場のために、素のファイルの取り出しを置き換えるものとして Hugging Face が作った経路であり、詰まった瞬間にそれを見捨てる既定は、一度に三つのことをする。作られた当の成果物を、この蓄えの層には任せられないと出荷されたコードの中で認めることになる。転送が持っていた途中までの状態を捨て、遅い道でファイルを丸ごとやり直すことになる。そして、本当の直しを生む圧力を取り除いてしまう。供給元はやり直しなら出荷する。認めるほうは、たいてい出荷しない。
   
   厄介ごとを構造の穴に変えるのは、大きさである。Kimi K3 の公開された重みは 96 の切れ端にわたって 1.56 テラバイトに達した。2.4 兆パラメータの成果物は同じ組に入るし、その隣に出る 27B の兄弟は、旗艦が実際には誰のためのものかについての表明である。その大きさでは、取り出しは押して済む一手ではなく、少なくとも一度は切れる回線の上で何時間も走る仕事になり、一度目でうまく通る見込みは切れ端が増えるほど下がる。それを引き受けているのは、一台の機械に重みを引いてくる個人ではない。参照になる重みを一度取ってきて、より小さい何かを出し直す仲立ちのほうであり、それこそ Unsloth が相手にしている層であり、この計画の公表の記録が転送の道具のそれのように読めるようになった理由でもある。
   
   これを決めるのは工程表ではなく、出荷された版である。この予測が外れるのは、Q2 2027 の終わりまでに、公表されたhuggingface_hub が、詰まったか失敗した XET の転送を見つけ、その同じファイルを素の HTTP の口で、環境変数を一つも置かず、呼び手が書いた例外の受けもなしに終わらせ、それが公表の記録か取り寄せの経路そのものの中で見て取れる場合である。三つのものはこれに反しない。やり直しを増やすこと、詰まりの見つけ方をよくすること、XET の内側での塊ごとの再開や速い仕組みは、この予測が否定されることではなく、まさに見込んでいる帰結のほうだ。HF_HUB_DISABLE_XET が使いやすくなっても、それは最初の一バイトが動く前に下される決めのままである。そしてさらに下流の計画が自前の逃げ道を出荷すること——提供の実行環境、手元で走らせる道具、写しの置き場——は、この主張を破るのではなく裏づける。肝心なのは、これがファイルを送る側ではなく受け取る側によって書かれ続ける、というところにあるからだ。

   In plain language: 巨大な AI のモデルのダウンロードはよく途中で止まる。Hugging Face は、昔ながらのダウンロードの方法に切り替えるのではなく、自分の仕組みを直し続ける。


2. 自律の侵入テストの供給元が、Q2 2027 までに CREST の AI の認定を取る

   反射で読めば、二つ目の出来事がインクの乾かないうちに一つ目を安いほうへ付け直した、ということになる。だがそこは見る場所として間違っている。代わりに問うべきは、自分から欲しいと決めたわけではない侵入テストを買うとき、顧客は何を買っているのか、である。その支出の大きな部分は、基準がそれを求めるから存在しており、そして基準は能力を求めてはいない。カード決済のデータの保安の基準が求めるのは、資格があり、組織として独立している試験者であり、その資格を与える証書の名も挙げている。米国の連邦のクラウドの認可の制度が求めるのは、評価を行うために認められた評価者である。どちらも、道具がどれだけ賢かったかは尋ねない。買われているのは、監査人が受け取る文書の上の、誰かの責めを負う署名である。そして Horizon3 は、その点を今日よりずっと前に認めていた。カード決済の基準に向けた同社自身の対応の品は、Horizon3 の Offensive Security Certified Professionals が届ける。人の試験者が、侵入テストの報告書と、それに添える是正のための報告書を顧客に渡し、顧客はそれを選んだ監査人に見せる。自律の基盤は、その人たちの下で走っている。この分野で最も自律に寄った会社が、署名されなければならない部分については、すでに資格を持つ人を請求書に載せているのである。

3. エージェントが書いた加速器の一式に、Q2 2027 までに外からの提供の数字が付く

   昨年 Google Brain を離れて Infinity を興した Jeremy Nixon は、自分のチームが AI のコーディングのエージェントをd-Matrix のシリコンに向け、CUDA 相当のソフトウェアをおよそ十時間で動かし、テンソル並列の行列積で Corsair という部品の理論上の頂のおよそ 92 パーセントに届いたと言う。十日のうちに、最前線のモデル三つが、どの層も一から書かれた状態でこの chip の上を端から端まで動いていたとも言う。書いているエージェント Ignition は、ある加速器がモデルをどれだけ効率よく動かすかを決める計算のカーネルを、作り、試し、詰めていく——歴史的に、挑む側の供給元に専門のチームと数年を要してきた仕事であり、移植がそもそもめったに起きない理由である。Infinity は先月、1 億ドルの評価額で 1,500 万ドルのシードを締めた。
   
   この話の中の数字はどれも当事者自身のものであり、そこに入っている二つの主張は同じ主張ではない。理論上の頂の九十二パーセントとは、シリコンが原理として出しうる演算に対する比であって、一つのカーネルの種類の上で、カーネルを書いた者が選んだ形と精度で、データはすでにあるべき場所に置かれた状態で測られる。これは本物の技術の成果であり、同時に、新しい部品について取れる最も見栄えのする数字でもある。端から端までの提供は別の計測で、しかもより難しい。名前の挙がったモデルを、述べられた精度、まとめての大きさ、文脈の長さで動かし、注意も、鍵と値の控えの行き来も、抜き取りも、行列積のベンチマークが一度も触れない細かな演算の長い尾も背負う。一式は、最も効く一つのカーネルの上で頂の近くに座りながら、毎秒のトークンでは負けることがありうる。誰もベンチマークにかけなかった演算こそが、詰まりを起こすものだからだ。Nixon のより強い主張——十日のうちに三つのモデルが端から端まで——こそが議論に決着を付けるはずのものであり、それが、隣に処理量の数字を伴わずに現れた。
   
   同じ報せの巡りは、堀がいまどこにあるのかについての意見の食い違いも運んできた。Rebellions の Marshall Choy は、推論において CUDA はもう効かないと言う。Modular の Chris Lattner は、CUDA が図形処理から受け継いだものを、脱ぎ捨てられない重荷として読む。Futurum の Daniel Newman は逆の向きを指す。Slurm のスケジューラを保守する SchedMD を十二月に NVIDIA が買ったことを挙げ、堀は流れ出たのではなく一式の上のほうへ移ったのだと論じる。議論はこれを解かない。解くのは、挑む側の部品を値踏みする人が、売り手から受け取らずに済む提供の数字を見つけられるかどうかである。
   
   だからこの予測は、誰が正しいかではなく、誰が公にするかに落ちる。Q2 2027 の終わりまでに、公に読める成果物が、カーネルもしくは翻訳の層が機械によって書かれたと述べられている、名前の挙がった NVIDIA 以外の加速器の上で動く、名前の挙がったモデルについて、端から端までの推論の処理量か待ち時間を報じ、しかも走らせ方の設定——モデル、精度、まとめての大きさか同時の数、系列の長さ——を、読み手が同じ走行を試みられる程度に近く開示する。その公にする側は、シリコンにもコードを作る側にも商いの利害を持たない。学の研究の集まり、独立した評価の団体、あるいは自分の計測を報じる顧客である。一つの境目だけは、あとからではなく前もって決めておく。MLCommons の Inference の回に載った結果は数に入る。出した側がハードウェアを動かしているとしても、開示の要件と査読が、出した側ではなく協議体のものだからだ。一式がどう作られたかは、この線引きに関わりがない。エージェントが Triton を出そうと MLIR を出そうと、エージェントが人の手の形をしたカーネルを出すのと同じだけ数に入る。ただし、その層が機械によって書かれたと公にする文が述べていることが条件である。
   
   この条件をすべて満たす成果物が 2027 年 6 月 30 日に公になっていなければ、これは偽として決まる。そうなる筋道は、取り立てて珍しくもないものが三つある。その計測を走らせるのに最も適した立場にいるのは、部品を売っている当人であり、独立した評価者は、買い手の層ができる前ではなくできたあとに現れる傾向がある。だから全体が、供給元の記事、報道向けの発表、基調講演の資料、創業者への聞き取りのままで終わりうる。どれだけ細かくなろうとも、である。頂に対する百分率にはそれ自身の重みがある——安く、見栄えがし、シードの段階の会社が一週間で出せる——だからその小さなベンチマークが、皆の引く数字であり続けるだけかもしれない。三つ目の筋道は、下地にある考えにとっての敗北ではないので、名を挙げておく値打ちがある。この分野が、正直な尺度として演算の網羅のほう、つまり作られた一式が枠組みのどれだけを実際に実装しているかに落ち着き、処理量の代わりにそれを報じるようになる、というものだ。そうなり、かつ利害のない公表者からの提供の数字が現れなければ、これはやはり偽として決まる。

   In plain language: ある新興の会社が、AI が十時間で chip のソフトウェアを書いたと言う。数に入るには、利害のない誰かがそれを測らなければならない。
