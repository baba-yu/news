1. ディスクから流し込む 80B の推論は、H2 2027 までに測り直されると毎秒 4.5 トークンに届かない

   8月4日に公になった Swift と Metal の実行環境 Swiftlet が、Qwen3-Next-80B——ディスクの上では 42 ギガバイトの重み——を、M5 の Mac で毎秒 4.5 から 5 トークン、常駐するメモリの山は 4.3 ギガバイトで生成させたと報せている。密な層を 4 ビットのまま常に載せておき、振り分けられる専門家のほうは記憶装置から、利用者がコマンドラインの指定で大きさを決めるキャッシュへ流し込む、というやり方によってである。仕掛けは本物で、算術も筋が通っている。このモデルはトークン一つあたりおよそ 30億のパラメータしか点火しないので、トークンごとに動かさなければならないのはファイルそのものではなく、その一部にすぎない。その主張が運んでいないのは、重みが常駐せずに流れ込むようになった途端、スループットの数字に意味を与えることになる条件の一式である。文脈の長さは示されていない。まとめて処理する数もない。指示文の処理と復号の切り分けもない。量子化は密な部分についてしか述べられていない。ここでは、それらの条件は帳簿の付け方であることをやめ、計測そのものになる。書き手自身の数字は、渡されるメモリの量によって専門家のキャッシュの当たり率が 43% から 70% のあいだで動くこと、そしてその範囲にわたってスループットがほとんど動かないことを示している。いまのところ詰まりは、記憶装置からの読み出しではなく GPU への仕事の送り出しにあるからだ。つまり速さを決めるのは、一回の走りがどれだけの送り出しを求めるかであり、それを決める条件こそ、書き手が一度も振らず、一度も述べなかったものである。長い指示文ほど、一回の生成のあいだに触れる専門家の種類は増える。そしてここにあるどの値も、外の誰にも名指せない文脈の長さのもとで取られている。それこそ、一つの数字では言い表せないものだ。今日のもう一つの手元での推論の一件も、同じ形をしている。Unsloth の Studio の取り込みは、その企て自身の GGUF の量子化の上に画像と動画の生成を加えたが、まとめて処理したときの速さの伸びはチームが自ら測ったもので、それを確かめるためのパッケージの公表は付いていない。予測は、ここでの見出しの数字が、キャッシュの温まった、文脈の短い、いちばん条件のよい場合の値であり、ほかの誰かに測られたら生き残らない、というものである。H2 2027 の終わりまでに、この実行環境の書き手ではない誰かが公表する計測——Apple のシリコンの上で、800億級の疎な MoE のモデルを専門家の流し込みで走らせたもの——が、毎秒 4.5 トークンを下回る復号の速さを、それが測られた文脈の長さとともに述べて報せる。これが外れる道は二つある。述べられたその条件の下でそうした計測が現れ、毎秒 4.5 トークン以上に着けば、中身の上で外れである。条件を述べた計測が 2027年の終わりまで一つも現れなければ、沈黙によって外れであり、この数字は今日のままにとどまる。一つの値、それを出した当人によるもの、そして外の誰にも条件を名指せない一回の走りについての記述である。

2. ChangXin Memory は、Q4 2027 まで米国の Entity List に載らない

   Nikkei Asia が今朝、HP、Asus、Acer が中国の ChangXin Memory Technologies の DRAM を、米国の外で売るノートパソコンに載せて出し始めたと報じた。部品の認定は、今年の半ばごろに終えていたという。その一文に付いた但し書きは、どれも荷を担いでいる。量は限られている。置き所は米国以外の市場の安い機種である。規制と地政学のさらされ方がより強い地域には、Samsung、SK Hynix、Micron が取ってある。そして HP は、この供給元に肚を決めたのではなく、まだ見定めている最中だと書かれている。握っておく値打ちがあるのは、その理由のほうだ。これは値段の決定ではない。供給の決定である。建て増しが、中国以外のメモリを行き渡らせるには足りないところまで持って行ったから下されたのであり、ノートパソコンを売る側がどれでも同じだと扱ってきた部品が、いまや一台が出荷できるかどうかを決めるものになっている。メモリと記憶装置の会議である FMS は、同じ朝に Santa Clara で二十回目を開いた。
   
   そこから生まれるのは二つの部品表である。一つは米国向け、もう一つはそれ以外の全部だ。そして気づくべきは、それを求める法がどこにもないという点である。ChangXin のメモリが入ったノートパソコンを小売が売ることを止める米国の決まりはないし、箱に誰のメモリかを書けと求める決まりもない。この分け方は私的な危うさの見立てであり、与えられた線ではなく、三つの会社が来ると見込んでいる線について下されたものだ。しかもそれが下されているのは、ワシントンがその線を本当に引くかどうかを決めつつある、まさにその季節である。
   
   実際にある制限は、別のところを指している。ChangXin は、中国の軍事企業と認定された企業についての国防総省の名簿に載っている。報道によれば、2月の草案が一度そこから外し、数時間のうちに引っ込められたあと、6月8日に公表された更新がそのまま載せ続けた。この掲載が届くのは連邦の調達であって、消費者のノートパソコンではない。輸出管理の仕掛けは、また別のところへ届く。2022年10月から、18 ナノメートルのハーフピッチ以下で DRAM を作るのに要る装置と技術を中国へ送るには許可が要る。これは ChangXin が買えるものを縛るもので、その結果この会社は、極端紫外線の露光なしで先の道筋を組んできた。フラッシュの側の相方である Yangtze Memory は、2022年の終わりから商務省の Entity List に載っている。ChangXin は載っていない。

3. リポジトリが持ち込むエージェントのフックが、Q2 2027 までに自前の承認を得る

   資格情報を盗むワームが8月4日、npm のレジストリを駆け抜けた。攻撃者が keyv——週におよそ 1億2,700万回引かれるキャッシュのライブラリ——の維持者の GitHub のアカウントを乗っ取り、そのリポジトリ自身の GitHub Actions の流れを使って、汚された版を切り出したのである。Aikido は中央ヨーロッパの昼過ぎまでに、1,381 の版にまたがる少なくとも 868 のパッケージを数え、まだ数え続けていた。同じ維持者の flat-cache、file-entry-cache、cacheable-request、そして @cacheable の名前空間も一緒に持って行かれており、及ぶ範囲は月あたり二十億回の導入を超える。この話の中で、数え上げよりも多くの仕事をしている細部が二つある。一つ目は、悪意のあるファイルが、版の札が付く前に各企ての main の枝へ入っていたことだ。だから汚された版は、正しい来歴の署名を持っていた。供給網を検める者が、このパッケージは問題ないと結論づけるために確かめる成果物は、設計どおりに働いたうえで、汚された組み上げを証したのである。それが証しているのは、ある組み上げがリポジトリの流れから出てきたということであって、誰かがリポジトリの中身を読んだということではないからだ。二つ目は、汚されたリポジトリが、セッション開始のフックを載せた `.claude/settings.json` と、フォルダが開いたときに火を吹くよう仕込まれた `.vscode/tasks.json` の仕事も一緒に出しており、どちらも同じ setup の script を指していたことである。
   
   この二つは同じ種類の失敗ではなく、この予測が扱うのは二つ目のほうである。供給網の侵害に対してこの生態系が組み上げてきたものは、すべて導入の時点を指している。lockfile、版の固定、導入時の script の無効化、隔てられた組み上げの機械、そしていまや来歴である。リポジトリが持ち込む起動時の項目は、その道をまったく通らない。開発者が、あるいはその代わりに働くエージェントが、企てを開いたときに火を吹く。つまりそれが降りるのは、捨てられることを前提に作られた組み上げのコンテナではなく、盗む値打ちのある資格情報を抱えた、作業に使う機械のほうだ。その前に立っている仕掛けは、ワークスペースを信頼するかどうかについての一度きりの決定である。誰かが仕事を始めようとしているその瞬間に、自分の意思で複製したフォルダについて下される。たいていの人が読まずに押して通る仕掛けであり、押して通る理由は、押して通れることこそがこの製品の役目だからである。これが降りた週は、セキュリティの暦がラスベガスに座る週だ。Black Hat の AI Summit は三年目に入り、BSides Las Vegas は初めての AI のセキュリティ専門の流れを開いた。どちらも、話に出るしくみはすでに資格情報と自律を握っているという、はっきり述べられた前提の上で、実務者に向けて張られている。今朝、その前提を論証しなければならない者は誰もいなかった。
   
   予測は、その信頼の一押しでは足りなくなる、というものである。Q2 2027 の終わりまでに、報道で名指しされた二つの製品——Anthropic の Claude Code か Microsoft の Visual Studio Code——の少なくとも一方が、ある既定を説明する。リポジトリが持ち込む、開いたときやセッションの始めに走る項目は、ワークスペースを信頼するという決定とは別の段で承認されるまで走らない、という既定である。何が走るのかを示す項目ごとの一覧を信頼の画面の中に置く形でもよいし、利用者が自分の側のどこかで有効にするまで項目を動かないまま留め置く形でもよい。求める水準は、公表の覚書か製品の説明書きに記され、ふつうに新しく入れた人にまで届く既定であることだ。
   
   惜しいところまで来ても数に入らないものがいくつもあり、そのどれもが、予測されているものより売り手にとって安い。だから一つずつ名を挙げる値打ちがある。切ったまま出荷される、利用者が自分で入れる固め方の設定は数に入らない。企業向けだけの方針の仕掛けは数に入らない。このワームが実際に届いた層は、自分の機械にリポジトリを複製する開発者だからである。項目はどのみち走ったうえで出る警告の帯も数に入らない。手引きも数に入らない。用心を勧める記事、セキュリティの勧告、説明書きの一節は、既定をそのままにしておく。第三者の拡張も数に入らないし、検査の道具がこれらのファイルを見つけて印を付けられるようになることも数に入らない——それは、これが降りうるもう一つの、より安い場所であり、屁理屈ではなく正直な外れ方である。市場は、門が無いことに、代わりに見つけ出すことで応えることができる。2027年6月30日に検査の道具の発見しか存在しないなら、これは外れとなる。
   
   商いの側の半分が、そもそもなぜ圧がかかるのかを説明する。導入の経路についての後始末の請求書はすでに書かれており、しかも小さくない。汚された版を引いたすべての組織が、仕込まれた中身の手が届きえた資格情報をいま入れ替えている。そのさらいは公開用のトークン、クラウドの鍵、クラスタのトークン、秘密の保管庫の資格情報にまたがっていた。会社が止められないしくみに触れる類の入れ替えである。開いたときの経路は、それを、誰も一覧を持っていない層の数だけ掛け合わせる。開発者がフォルダを開いたことを記録する lockfile は、どこにもないからだ。この一年、自分たちのリポジトリの前にコードを書くエージェントを据えてきた会社は、いま自社のセキュリティの部門から一つの問いを向けられており、今日のところ正直な答えは一つしかない。リポジトリを信頼すると言った時点で、エージェントはリポジトリが走らせろと言うものを走らせる、というものである。Deliveroo、Qlik、Picsart に紐づく版も広がりの中に巻き込まれた。製品の既定を調達の問いへ変えるのは、そういう類の名前の並びである。
   
   いちばん強い反論は、その手間が全員に、いつまでも、すべてのリポジトリのすべてのセッションの最初の十秒に課されるということだ。しかもこの規模で起きたのは一度である。そして売り手にはすでに指させる答えがある。信頼の決定は存在し、利用者がそれを下した、という答えだ。二つ目の反論は、害を受ける層と買う層が同じではない、という点である。だから企業に売る方針の仕掛けが最も抵抗の少ない選択肢になり、それは上で外したばかりの惜しい外れである。三つ目は逆の向きに切り、しかも静かだ。承認の段がまったく目に見えないまま、この変化が届くことがありうる。利用者が手で設定していないリポジトリでは、これらの項目をただ動かないままにしてしまう、という形である。新しい画面を探して公表の覚書を眺めている読み手は、それを見落とすだろう。それでもこれは数に入る。主張は、リポジトリが持ち込む起動時の項目が、信頼の一押しだけを頼りに走ることをやめる、というものであって、新しい問いかけの箱が現れる、というものではない。

   In plain language: ワームが、コードの道具が自動で走らせる企てのファイルの中に、起動時の命令を隠した。それらの道具は、まず尋ねるようになると見てよい。

- 資格情報を盗むワームが今日、npm のレジストリの中を駆け抜けた。攻撃者が keyv——週におよそ 1億2,700万回引かれるキャッシュのライブラリ——の維持者の GitHub のアカウントを乗っ取り、そのリポジトリ自身の GitHub Actions の流れを使って、汚された版を切り出したのである。悪意のあるファイルは、版の札が付く前に各企ての main の枝へまっすぐ入っていた。だから汚された版は、正しい来歴の署名を持っている。供給網を検める者が、このパッケージは問題ないと結論づけるために確かめる、まさにその成果物である。Aikido は中央ヨーロッパ時間の昼過ぎまでに、1,381 の版にまたがる少なくとも 868 のパッケージを数え上げ、まだ数え続けていた。同じ維持者の flat-cache、file-entry-cache、cacheable-request、そして @cacheable の名前空間も一緒に持って行かれており、及ぶ範囲は月あたり二十億回の導入を超える。仕込まれた中身は、組み上げ済みの束を取ってくる、導入の前に走る script である。npm のトークン、短命な OIDC のトークンを含むあらゆる種類の GitHub の資格情報、AWS の鍵とインスタンスメタデータの資格情報、Kubernetes のサービスアカウントのトークン、Vault と Stripe と Slack の鍵、SSH の鍵、Docker の設定、Terraform の状態をさらい、暗号化して攻撃者の持つリポジトリへ押し出す。その道が塞がれているときのための、控えの宛先も備えている。そのうえで、見つけた公開用のトークンを使って自分自身を公表し直す。研究者たちが、二分から七分ごとに組織から組織へ移っていくのを見ていたのは、そのためである。コードを書くエージェントを走らせている者にとって、立ち止まる値打ちがあるのはここだ。汚されたリポジトリは、`.claude/settings.json` に載せたセッション開始のフックと、フォルダを開いたときに火を吹く `.vscode/tasks.json` の仕事も一緒に出しており、どちらも同じ setup の script を指していた。開発者が企てをエディタやエージェントで開いたときに動き出す、二本目の実行の経路である。導入したときではない。どちらも利用者がワークスペースを信頼していることを要るが、それは、たいていの人が読まずに押して通る仕掛けである。Deliveroo、Qlik、Picsart に紐づく版も、広がりの中に巻き込まれた。 [Aikido - Keyv and friends compromised in npm supply chain attack](https://www.aikido.dev/blog/keyv-and-friends-compromised-in-npm-supply-chain-attack), [The Hacker News - Keyv-linked npm worm poisons hundreds of packages, plants Claude Code and VS Code hooks](https://thehackernews.com/2026/08/keyv-linked-npm-worm-poisons-hundreds.html), [Cybersecurity News - Keyv npm package with 127M weekly downloads compromised in Shai-Hulud attack](https://cybersecuritynews.com/keyv-npm-package-compromised/)


### 800億パラメータの Qwen が、専門家をディスクから流し込んで、Mac の 4.3 GB のメモリで動く

- Swift と Metal で書かれた Swiftlet という実行環境が今日公になり、述べるのは易しく、反論するのは厄介な主張を持ち込んだ。Qwen3-Next-80B、ディスクの上では 42 ギガバイトの重みが、M5 の Mac で毎秒 4.5 から 5 トークンを生み、常駐するメモリの山は 4.3 ギガバイトに収まる、というものである。350億パラメータの Qwen3.6 は同じやり方で 2.6 ギガバイトに収まり、毎秒 7 から 11 トークン。iPhone 17 の上ではおよそ 2.5 ギガバイトで、毎秒およそ 1 トークンである。仕掛けは新しい量子化ではなく、造りのほうにある。これらはトークン一つあたりおよそ 30億のパラメータにしか触れない疎な MoE のモデルなので、実行環境は密な部分——注意、埋め込み、振り分け役——を 4 ビットのまま常に載せておき、振り分けられる専門家のほうは、一度の読み出しで取り出せる決まった歩幅の入れ物に詰めておく。そして、振り分け役が求めた専門家だけを流し込み、近ごろのものとよく使うものを、利用者がコマンドラインの指定で大きさを決めるキャッシュに抱えておく。層の四分の三にわたる Gated DeltaNet の線形の注意が、鍵と値のキャッシュが節約分を食い返すのを止めている。書き手は、渡すメモリの量によってキャッシュの当たり率が 43% から 70% のあいだで動くと報せている。そしてより面白いのは、その持ち分が変わってもスループットはほとんど動かないという点だ。いまのところ詰まりは、記憶装置からの読み出しではなく、GPU への仕事の送り出しにあるからである。見ておくべきはその数字だ。流し込みという道にはまだ余地が残っていることを言っており、電話やノートパソコンの上のメモリの天井を、容量の問題ではなく段取りの問題として置き直すからである。許諾は Apache 2.0、commit は八つ、そしてコードを書くエージェントとともに書かれている。 [GitHub - Swiftlet, a Swift and Metal runtime for 35B and 80B Qwen on Apple devices](https://github.com/leonickson1/Swiftlet), [Hacker News - Run an 80B Qwen in 4.3 GB of RAM on a Mac, and a 35B on an iPhone](https://news.ycombinator.com/item?id=49158333)


### Unsloth Studio が画像と動画の生成に手を伸ばし、画像のモデルへの LoRA の学習も加える

- Unsloth のここしばらくで最大となる一件の取り込みが今日降りた。しかも文章についてのものではない。デスクトップ版の Studio に向けたプルリクエストが、Images の頁を加える。Z-Image、Qwen-Image、FLUX、SDXL の派生について、Unsloth 自身の GGUF の量子化の上で走る、文章からの画像の生成。変形、描き足し、拡張、拡大、そして指示による手直しを覆う編集の流れ。音声を同期させた、五つのモデルの系統にまたがる文章からの動画。そして、微調整を追う読み手にとって効いてくる部分——画像のモデルへの QLoRA の学習で、その場で見える指標と、出来上がったアダプタの一押しでの配りが付く。その下には推論の経路が二つ——native の stable-diffusion.cpp と Diffusers——が座っており、GPU のメモリを会話の側の仕組みと取り合うのではなく分け合う。条件付けと組み上げのキャッシュとあわせて、画像をまとめて描き出すやり方を、チームは自ら、同じ画像を一枚ずつ順に描き出す場合より 10 倍から 22 倍速いと測っている。差分は 231 のファイルにわたる 79,151 行の追加で、八百を超える裏側の単体の試験と、browser の高さでの端から端までの確かめを運んでいる。同じ日にさらに 28 の commit が入った。その中には、Windows の導入器における Intel Arc の見分けと XPU 版 PyTorch の導入の経路がある——Arc、Iris、UHD、HD graphics がいま見分けられるようになり、wheel は自前の oneAPI の実行環境を同梱するので、Intel の道具一式を別に入れる必要はない——さらに、公表の流れを固める一連の仕事も入った。署名の付いた導入器のプラグインのライブラリ、署名のないファイルが一つでもあれば失敗する公表、取りに行くのではなく埋め込まれる WebView2 の起動用の部品、公表の前に Defender で走査される Windows の束、そして失敗したらやり直す macOS のディスクイメージの綴じ付けである。そのどれにも、パッケージの公表は付いてこなかった。Python のライブラリはいまも PyPI の、昨日の 2026.8.2 のままで、説明書きの変更の記録は7月29日から動いていない。だから今日の変化が見えるのは、リポジトリの中だけである。 [GitHub - Studio: add image generation, editing workflows and LoRA training with Unsloth GGUFs](https://github.com/unslothai/unsloth/pull/6763), [GitHub - Add Intel Arc GPU detection and XPU PyTorch install to Windows installer](https://github.com/unslothai/unsloth/pull/7706)
