## Future


1. Redis は H1 2027 までに、CVE も CVSS も付かない遠隔コード実行のおそれのある修正をもう一つ出す

   Redis は7月23日木曜の晩に七つのリリースを公開した——6.2.23、7.2.15、7.4.10、8.2.8、8.4.5、8.6.5、8.8.1 で、すべてがおよそ百分のあいだに収まっている——そしてそのどれもが、同じ二つの不具合の系統を扱うセキュリティの告知を伴っている。細工したストリームの RESTORE のペイロードは、二つの消費者に一つの未確認の記録を共有させたまま残すことができ、use-after-free を生む。同梱の RedisBloom と TDigest の構造に向けて細工した RESTORE のペイロードは、境界外への書き込みを強いることができる。Redis 自身の注記は、どちらも遠隔でのコード実行に至りうると述べている。その注記が運んでいないのは、どちらの系統についても CVE の識別子と CVSS のスコアである。七つのリリースは、同じ二つの修正を分け合って取り込んだ七つの保守中のブランチであって、七つの別々の欠陥ではない。どちらの経路も RESTORE の権限を持つ認証済みのセッションを要し、Redis が示す暫定の緩和は、その権限を取り上げ、信頼できない網からポートを外しておくことである。
   
   予測はこうだ。欠けている識別子は見落としではなく順序の判断であり、そしてそれが繰り返される。H1 2027 の終わりまでに、Redis はさらに少なくとも一つ、メモリの破壊またはコード実行の影響を保守側自身の言葉で述べながら、公開の時点で CVE の識別子も CVSS のスコアも付けないセキュリティのリリースを出す。
   
   これを押しているのは、開示の二つの半分のあいだにある速さの食い違いだ。見つけて直すほうは自動化されつつある——検査の仕掛けの生成、計測を仕込んだビルド、デバッガのもとでのクラッシュの選り分けである。一方で識別子の割り当ては、人の速さで進む申請と審査の回りものにとどまり、番号と採点されたベクトルが出てくるのは数日から数週間あとになる。支えている範囲のすべてを二時間かからずに切って試して印を付けられるプロジェクトには、まず修正を出し、書類はあとから追わせる理由が十分にある。費用は下流に落ちる。企業が何をいつ当てるかを決める仕掛けは、識別子と深刻度のしきい値で照合するからだ。ディストリビューションのセキュリティの追跡表も、依存関係の走査も、法令順守の確認も、すべて CVE を鍵にしている。だから、識別子もスコアも持たない、保守側の言葉によるコード実行の欠陥は、そのどれからも見えない。6.2.22、7.4.9、8.6.4、8.8.0 に対する公の実証コードはすでに存在しており、攻める側は記録に載っている一方で、守る側の索引は空のままである。
   
   由来について但し書きを一つ。この話に付いている数字は確認されていないからだ。研究者の Chaofan Shou は、Kimi K3 が駆動するエージェントがおよそ90分で 19 件の zero-day の発見を掘り出し、27分で実際に動く攻撃を組み上げたと報告している。件数も所要時間も、主張されている自律も、すべて本人の申告であり、Redis の公の記録が裏づけているのは欠陥と修正だけである。この予測は、それらの数字のどれにも寄りかからない。寄りかかるのは、確かめられるほうだ。広く本番で使われているデータストアが、採点も識別もされないコード実行の階級の修正を、保守しているすべてのブランチにわたって、一晩で出した、という事実である。この主張は二通りに外れる。Redis の次のメモリ安全またはコード実行のリリースが、公開の時点で CVE の識別子と CVSS のスコアを付けて届くなら、割り当ての工程は追いつけていたことになり、予測は誤りである。H1 2027 が閉じるまでに Redis がそうしたリリースを一つも出さないなら、観察するものがなく、これも予測は誤りである。7月23日の二つの系統に何か月も経ってから遡って割り当てられても、この主張は救われも沈みもしない——問うているのは、注記が世に出るときに何を運んでいたか、である。

   In plain language: Redis は二つの深刻な不具合を素早く直したが、標準の不具合の番号と深刻度の点数を飛ばした。だから修正の道具からは見えない。同じことがまた起きると見込まれる。

3. 中国のオープンな重みへの米国の制限は、H1 2027 までに、ダウンロードではなく提供のほうに当たる

   The New York Times は7月25日土曜、政権のいまの傾きは、国家安全保障を理由として、一律の禁止ではなく名指しした特定の中国のオープンな重みのモデルへ的を絞った制限にある、と報じた。報道が名前を挙げているモデルは Kimi K3 である。描かれている仕組みは規則ではなく積み重ねであり——制裁と調達での圧力と柔らかな合図が寄り集まって、宣言された禁止ではなく、じわじわ効く禁止の形をとる——そして報道は、これでは自前でホストする側が読んで従える一本の法令がどこにも残らない、とはっきり述べている。予測はこうだ。その欠けている法令は、あとで誰かが埋める隙間ではなく、この事柄の変わらない形である。H1 2027 の終わりまでに、名前の挙がった中国のオープンな重みのモデルに対して効いている米国の制限は、提供と調達の層に見えるだけで、ほかのどこにも見えない。米国で法人化された推論の提供者かクラウドのモデルの目録が少なくとも一つ、連邦の指針か調達の要件か国家安全保障上の懸念を挙げて、特定の中国のオープンな重みのモデルを名指しで提供していないし今後もしない、と公に述べる。その一方で、米国の人が同じ重みを取得すること、あるいは保持することを禁じる、公表された米国の法令は存在せず、そのモデルの第三者による写しと量子化された変換は、米国から届くホストからなお取得できる。
   
   制限がそこに落ちるのは、相手方がいるのが提供の層だけだからだ。調達での圧力には、連邦の契約を持つ供給者が要る。柔らかな合図には、合図を受け取れて、それを受け止める法務を抱えている相手が要る。チェックポイントを落として自前で動かす人は、そのどちらでもない。そして今日のもう一つの公開が、その層が実際にどう見えるかを示している。Kwaipilot は KAT-Coder-V2.5-Dev を Apache 2.0 のもとで Hugging Face に公開した——総計 350 億パラメータ、トークンごとに 30 億が動き、カード一枚に収まる大きさである——リポジトリが作られたのは7月23日、最後に更新されたのが7月25日だ。日曜までに、その基準のリポジトリが引かれた回数はおよそ 3,800 である。一方、同じ期間に公開された共同体による GGUF への変換は、およそ 22,000 回引かれている。六対一に近い。公開した側のリポジトリは保管庫であり、見知らぬ誰かの量子化のほうが配り先だ。そしてライセンスはその再投稿を積極的に許している。公開した側のリポジトリを名指しする制限は、大半の人が実際に取得する成果物を名指ししていない。派生を名指ししようとする制限は、見知らぬ人たちがそれを作る速さより速く数え上げなければならない。
   
   もう半分は、二つの時計のほうだ。ホワイトハウスの自主的なフロンティアのモデルの枠組みは8月1日までに固まるとされており、対象となるモデルについて連邦の各機関に最長30日の公開前の確認の期間を与える。OpenAI と Anthropic と Google が内側にいて、Meta はいまのところ加わっていない。この道具は、協力する公開者からの事前の知らせだけで回っている。Moonshot の K3 の重みは7月27日月曜に公開される。モデルの名を挙げた報道の二日後であり、Kwaipilot の示すところでは、第三者による変換はリポジトリが公になってから数日のうちに現れる。つまり同じ政権が、自ら手を挙げるラボには公開前の確認を、それ以外には写しが出たあとの名指しを走らせており、掴めるものがあるのは最初の時計だけである。これは、OpenAI が目に見えて跨いでいる立場を解く形でもある。OpenAI は、オープンなモデルを先回りして禁じないことを求めのなかに含む7月24日のオープンな重みの書簡に加わりながら、中国のモデルへの制限を非公開に働きかけているとも別途伝えられている。名の挙がったモデルを載せないと決めることは、オープンなモデルを禁じることではない。
   
   これを壊すのは能力だ。報道が挙げる、もっと強く踏み込まない理由は、中国のオープンなモデルがサイバーセキュリティのベンチマークでなお西側の先頭を走るものに後れている、というものである——原則ではなく、現在についての判断だ。その判断の見えている縁が Redis の試みである。研究者の Chaofan Shou は、Kimi K3 が駆動する32のエージェントが協調しておよそ90分で Redis の zero-day を 19 件掘り出し、別の実行では認証済みの遠隔コード実行の実証コードを27分で作り上げたと報告している。件数も所要時間も、主張されている自律も、すべて本人の申告である。Redis の公の記録が裏づけているのは、二つの RESTORE の不具合の系統と、7月23日木曜の晩にその修正を取り込んだ七つの保守中のブランチであり、CVE の識別子も CVSS のスコアも付いておらず、何が見つけたのかについては何も述べていない。この種の主張が独立に再現されれば、抑制のためのベンチマークの論拠は消え、報道が脇へ置かれたと言う一律の道具が戻ってくる——そして一律の道具は、ダウンロードにまで手が届く種類のものだ。だからこの予測は、どちらの向きにも外れうる。H1 2027 の終わりまでに、米国の提供者も目録も名指しの公の拒否を出しておらず、この傾きが報道の外へ出ないままなら、予測は誤りである。逆に、公表された米国の法令が保持やダウンロードにまで届き——米国の人が名の挙がった重みを取得することを違法にするか、基準のリポジトリと並んで写しまで下ろさせるなら——別の向きに誤りである。

由来のところが、これから議論になる部分だ。研究者の Chaofan Shou は、Kimi K3 が駆動する32のエージェントが協調して——ソースを取得し、ファザーを生成し、ビルドに計測を仕込み、GDB のもとでクラッシュを追って——およそ90分で Redis の zero-day を 19 件掘り出したと報告している。さらに別の実行では、8.8.0 に対する認証済みの遠隔コード実行の実証コードを27分で作り上げた、とも述べている。実証コードは 6.2.22、7.4.9、8.6.4、8.8.0 に対して公に投稿されている。件数も所要時間も、主張されている自律の度合いも、すべて本人の申告である。Redis の公の記録が裏づけているのは欠陥と修正だけで、そこから先には何も及ばない。そして7月24日の時点で、実際に悪用されたという報告は出ていない。OpenAI の事案と並べて読むと、有益な違いが見えてくる。この試みは、名前の出ている研究者によってオープンソースのプロジェクトへ向けられ、出荷された修正で終わった。同じ能力の、守る側が求めているほうの姿である。 [Redis - release 8.6.5 security fixes (July 23, 2026)](https://github.com/redis/redis/releases/tag/8.6.5), [The Hacker News - Kimi K3 agents found Redis zero-days and built RCE exploit, researchers say](https://thehackernews.com/2026/07/kimi-k3-agents-found-redis-zero-days.html), [SecurityOnline - Critical Redis patches fix RCE and memory corruption flaws in RESTORE](https://securityonline.info/redis-rce-vulnerabilities-memory-corruption-restore-command-patch/), [heise online - Kimi K3 finds several zero-day vulnerabilities in the Redis database](https://www.heise.de/en/news/Kimi-K3-Chinese-AI-finds-several-zero-day-vulnerabilities-in-redis-database-11377430.html)


### Kwaipilot が KAT-Coder-V2.5-Dev を Apache 2.0 のもとで公開する。総計 35B、稼働 3B——カード一枚に収まる大きさのオープンなコーディングのモデルであり、その GGUF は基準となる重みを六対一で引き離している

- Kuaishou の Kwaipilot チームが、自社の KAT-Coder の系列のオープンな重みの兄弟を Apache 2.0 のもとで Hugging Face に置いた。仕様は、同じ報道の周期を占める一兆パラメータ級の公開の隣に並べると、意図してつつましい。KAT-Coder-V2.5-Dev は混合エキスパートのモデルで、総計 350 億パラメータ、トークンごとに 30 億が動く。Qwen3.6-35B-A3B を土台に、7月の初めに出たホスト提供の KAT-Coder-Pro V2.5 と同じ、教師ありの微調整と強化学習の手順で後段の学習を経ている。BF16 の safetensors として配られ、Transformers、vLLM、SGLang、KTransformers の上で動く。報告されているスコアは、SWE-bench Verified で 69.40、SWE-bench Multilingual で 63.00、PinchBench で 93.43 である。モデルカードが率直に述べている但し書きが一つある。今回のオープンな公開に含まれるのは言語モデルの重みだけで、挙動はテキスト専用のモデルになる——この系列の視覚と多様式の部品は入っていない。だからオープンな成果物は、名前の由来になったホスト提供の製品より狭い。
