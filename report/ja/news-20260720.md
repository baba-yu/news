3. オープンソースのベクトルデータベースが、H1 2027 までに認証を既定で有効にして出荷する

   CVE-2026-59218 は、9.8 と評価された、認証を経ないリモートコード実行への経路であり、標的は Milvus——最も広く配備されているオープンソースのベクトルデータベースで、検索拡張生成(RAG)の背後にある埋め込みを保持するストアである。メンテナは修正を出荷したが、長く効く助言は運用の側にあった。公開インスタンスをインターネットから外し、ポートを閉じ、プロセスが読めた認証情報はすべて入れ替えること、である。これはソフトウェアによる強制ではなく境界の衛生管理であり、外部にさらされた推論の話が繰り返し見つけてきたのと同じ弱点に行き着く。ベクトルストアは信頼された私設のサブネットに置かれることを前提に作られたため、ポートを開けたまま認証もなしが真っ当な既定として通り、そして RAG の配備は、チャットボットを動かすために、そのうちの数千を公開の IP へ押し出した。検索の層が、ありふれたデータベースより悪い侵害になるのは、何が漏れるかによる。組織がモデルに与えた非公開のテキストが、保存された埋め込みと、その隣に保たれた元のチャンクとから復元できてしまうのだ。予測は、その是正が運用手順ではなくソフトウェアのほうにやって来る、というものである。これは Redis、MongoDB、Elasticsearch がそれぞれくぐった周回だ——開いたインスタンスへの大量のスキャンが、保護モード、ループバックを既定とする束縛、そして認証情報のない到達可能な束縛を拒む本番向けの検査を強いた——そしてベクトルデータベースは、まだこれを経ていない。H1 2027 までに、主要なオープンソースのベクトルストアのうち少なくとも2つ——Milvus、Qdrant、Weaviate、Chroma、そして pgvector を用いるサービングの前段のなかで——が、認証情報のないままループバック以外のインターフェースに束縛しようとする操作を、拒む、ループバックへ差し戻す、あるいは明示的な了解の後ろに置くリリースを出し、しかもそれを、任意の堅牢化の手引きとしてではなく、リリースノートに互換性を壊す既定値の変更として記す。日程を決めるのは、良心ではなく調達である。名の挙がった、インターネットに面した導入の母数を伴う 9.8 の CVE は、ポートを閉じ認証を有効にすることを、サポートフォーラムの提案から買い手の確認表の項目へと変える。そして、堅牢化のページを決して開かない運用者にまで届く制御は、出荷時の既定値だけなのだ。


   In plain language: 厄介なバグのせいで、企業の非公開の AI 文書を保存するデータベースに攻撃者が入り込めてしまった。だからこれらのツールは、ほどなく既定でパスワードを求めるようになる。

- 2026年にエージェントの基盤を静かに組み替えつつある問いは、どのフレームワークが最も美しいエージェントのループを書くか、ではない。作業の途中でサーバーが再起動しても生き延びるのはどれか、である。そして今週、それが具体的な一手を生んだ。<a href="https://blog.langchain.com/langgraph-durable-execution-ga/">LangChain が LangGraph 向けに永続的な実行を出荷した</a>。<a href="https://github.com/langchain-ai/langgraph/releases/tag/v1.1.0">その v1.1.0 のリリース</a>で、エージェントの実行の各ステップを永続的な状態にチェックポイントとして残し、クラッシュしたり再デプロイされたワーカーが、作業をやり直したり失ったりせずに、最後に完了したノードから再開できるようにした。これは、<a href="https://thenewstack.io/durable-agent-execution-langgraph-temporal-2026/">Temporal を、長時間動くエージェントの既定の土台にしてきた</a>訴えへの、まっすぐな回答である。Temporal は、OpenAI が Codex を動かしている永続的な実行のエンジンであり、Mistral の Workflows 製品の下にも座っている。3者が共有する見立てはこうだ。本番のエージェントとは、実のところ分散ワークフローである。1件あたり数十秒から数分、多数のモデル呼び出しとツールの起動が入り混じり、その途中でネットワークの障害やデプロイが起きる。そこで面白い保証は、知能ではなく、生き延びられることのほうだ。LangGraph が永続的な実行を、別のワークフローエンジンにエージェントのループを継ぎ足すのではなく、フレームワークそのものの中で実現したことは、コード優先の陣営にとって2つの層を1つに畳み込む。これがバージョンの注記を超えて効いてくるのは、エージェントの障害の見え方を変えるからだ。故障の型が「エージェントが何をしていたか忘れた」ではなくなり、「エージェントはいったん止まり、中断したところから引き継いだ」になる。これは、デモと、銀行が本番で回すものとの違いである。オーケストレーションの市場はその性質を軸に集約しつつあり、それを任意の機能として扱ってきたフレームワークは、いまになって後付けしている側なのだ。 [LangChain Blog - Durable execution for LangGraph](https://blog.langchain.com/langgraph-durable-execution-ga/), [The New Stack - Durable agent execution: LangGraph answers Temporal](https://thenewstack.io/durable-agent-execution-langgraph-temporal-2026/), [GitHub - langchain-ai/langgraph v1.1.0 release](https://github.com/langchain-ai/langgraph/releases/tag/v1.1.0)
