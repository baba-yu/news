- **新ベンチマーク EvoArena、エージェントは世界の変化につれてずれていくと判明し、スコアは39.6%** — 6月の arXiv 論文2本が、エージェントとは何かを捉え直し、その持ちこたえ方を検証している。『Agentic Software: How AI Agents Are Restructuring the Software Paradigm』(arXiv:2606.05608)は、LLM エージェントはソフトウェアの根本的な再構成だと論じる。コードがあらかじめ書かれた判断ロジックを担うのではなく、エージェント自身がソフトウェアであり、その判断ロジックは実行時に生成される。これはライセンス販売型ソフトウェアから SaaS、そして agent-as-a-service への移行だという。実証面では、EvoArena(arXiv:2606.13681、6月11日)が、環境が段階的な更新を通じて変化していく中で、エージェントが知識の整合を保てるかどうかを、ターミナル・ソフトウェア・ソーシャルの各領域で検証する。現行のエージェントの成績は振るわず、平均正答率は39.6%にとどまる。著者らは EvoMem を提案している。これはメモリを構造化された更新履歴として記録するパッチ方式のメモリ手法で、EvoArena を平均1.5%引き上げつつ、GAIA と LoCoMo をそれぞれ6.1%、4.8%改善したと報告されている。これにより、静的なベンチマークは長時間動作するエージェントの頑健さを過大評価する、という指摘がいっそう鮮明になっている。 [arXiv - Agentic Software: How AI Agents Are Restructuring the Software Paradigm](https://arxiv.org/abs/2606.05608), [arXiv - EvoArena: Tracking Memory Evolution for Robust LLM Agents in Dynamic Environments](https://arxiv.org/abs/2606.13681)

1. DiffusionGemma が2027年Q2までにオープンウェイトのテキスト拡散モデル学習という新カテゴリを生み出す

   6月12日に公開された Unsloth の 2026.6.7 ベータは、これまでオンデバイスのファインチューニング基盤が成し得なかったことを実現した。Google のテキスト拡散言語モデル DiffusionGemma を、ダウンロード可能なローカルアプリの中で直接実行・学習できるようにしたのだ。同時に、Gemma 4 のマルチトークン予測、音声チャット、そしてメモリ使用量を約3分の1に削減するという量子化対応学習(QAT)も取り込まれた。テキスト拡散言語モデルは、左から右へ1トークンずつ生成するのではなく、トークンのブロック全体を並列にノイズ除去する仕組みを持つ。これまでは研究論文やホスト型デモの中にほぼ閉じこもっており、コンシューマ向けハードウェアでファインチューニングする正規の道筋は存在しなかった。Unsloth は、自己回帰型の LoRA、投機的デコーディング、学習後量子化をすでに扱う同じローカルツールチェーンに DiffusionGemma を組み込んだ。これにより拡散言語モデルは、論文上の珍しい存在から、実務者が自宅で実際に学習後調整できるものへと変わった。これが一過性ではなく「種(シード)」だと言える構造的な理由は、ローカルのファインチューニング・エコシステムの残りの部分にある。ランタイム(llama.cpp、Ollama、LM Studio、MLX)も、他の学習ライブラリ(Axolotl、TRL、torchtune)も、現時点では拡散言語モデルのノイズ除去グラフを事実上サポートしていない。つまりこの形式は、それを動かしたり学習したりする態勢がまだ整っていないエコシステムに対して出荷されたわけで、まさにその空白こそカテゴリが埋めようとして形成される場所である。先を見据えた本予測の中核は、オープンウェイトでローカル学習可能なテキスト拡散言語モデルが、単一の「Unsloth 上の DiffusionGemma」というチェックポイントにとどまらず、確立されたカテゴリへと固まっていくという点にある。具体的で反証可能な実現条件は次のとおり。2027年Q2(2027-06)までに、次のいずれかが成立すること。第一に、Google 以外の発行元から、独立した第二のオープンウェイトのテキスト拡散言語モデル系列(離散拡散または連続拡散、あるいはマスク型ノイズ除去)が、独自のモデルカードとダウンロード可能なウェイトを伴い、寛容なライセンスまたはオープンライセンスの下で出荷されること。その生成方式は自己回帰ではなく拡散に基づくものであること(候補としては Alibaba/Qwen、Mistral、Inception/Mercury 系のグループ、あるいはオープンウェイトを公開する研究室などが挙げられる)。第二に、Unsloth 以外の主要なローカル学習・推論スタック(llama.cpp、Ollama、LM Studio、MLX、Axolotl、TRL のいずれか)が、テキスト拡散言語モデルをコンシューマ向けまたはエッジ向けハードウェア上でネイティブに学習・実行するための、第一級かつ文書化されたサポートを出荷すること。ウェイト未公開の純粋な研究論文、ダウンロード可能なチェックポイントを伴わないホスト型 API 専用の拡散モデル、Google または Unsloth による DiffusionGemma 自体の追加リリース、あるいは Unsloth の既存経路を単にラップしただけのランタイムは、いずれも該当しない。指標となるのは、独立した第二のオープンウェイト拡散言語モデル系列、もしくは拡散言語モデルのグラフに対する真の意味での第二スタックのローカルサポートである。2027年6月30日の時点で、ローカル学習可能なオープンウェイトのテキスト拡散言語モデルが「Unsloth 上の DiffusionGemma」のみであり続け、第二の主要スタックがネイティブサポートを出荷していない場合、この予測は外れとなる。


   In plain language: Unsloth は自宅で学習できる初のテキスト拡散 AI を実現した。まもなく対抗モデルがこれを真似るか、他のアプリがこれを動かせるようになる。


2. SpaceX が2027年Q2までに xAI 部門の財務を公開 SEC 提出書類で区分開示する

   SpaceX は6月12日、ティッカー SPCX で Nasdaq での取引を開始した。固定価格の1株135ドルで約5億5,560万株を売り出し、およそ750億ドルを調達した。これは史上最大の IPO である。株価は約19~20%上昇して161ドル近くで引け、評価額は2兆ドル超となった。AI にとって重要なのは、xAI がいまや公開企業の内部にあるという点だ。Musk は2月、すでに X プラットフォームを取り込んでいた xAI を SpaceX に統合し、その取引は統合グループを1.25兆ドルと評価した。これにより、フロンティアの AI ラボが今サイクルで初めて米国の上場企業の財務に載ったことになる。非公開企業であった頃の xAI は、売上、損失、資本集約度を公表する必要が一切なかった。だが新たに上場した提出者の一部門となれば、その不透明さを保つのは難しくなる。米国の証券規則の下では、登録者は重要な事業セグメントを開示しなければならない。そして2兆ドルの評価額を支払ったばかりの投資家は、その評価が xAI/X 統合に一部裏打ちされていることもあり、企業全体のうち AI 部門が実際にどれほどを占めるのかを経営陣に問い詰めるだろう。先を見据えた本予測の中核は、この圧力が一行のナラティブな言及ではなく、実際の項目別開示へと転じるという点にある。具体的で反証可能な実現条件は次のとおり。2027年Q2までに、SpaceX が xAI 部門または AI 部門の財務(AI/xAI 事業に帰属する売上、営業利益または損失、もしくは設備投資)を、公開の SEC 定期提出書類(10-Q、10-K、または同等の登録書類)の中で開示し、それが EDGAR で確認できること。報告対象の事業セグメントとして、あるいは経営陣自身が示す定量化された AI 部門の数値として開示されること。該当しないものは次のとおり。数値を伴わない xAI への定性的言及。AI の区分けがない連結合計のみ。アナリスト推計、報道上の数値、あるいは提出書類自体が確約しない Musk の決算説明会での補足発言。私的な投資家向け資料にのみ現れ、公開の SEC 書類には出てこない数値。反対側のリスクは、SpaceX が xAI を区別のない合計に連結し、AI 事業は別個に報告対象となるセグメントではないと主張する可能性だ。その場合、2027年半ばまで同部門の経済性は開示されず、推測に委ねられたままとなる。


   In plain language: SpaceX は内部に xAI を抱えたまま上場した。そのため、まもなく公式報告書で xAI がどれだけ稼ぐか損するかを示さざるを得なくなる。


3. 機密 GPU の証明(アテステーション)が2027年Q2までにクラウド AI の契約条項として定着する

   Apple は Private Cloud Compute を Google Cloud 上で動かすことを決めた。Apple Foundation Model の推論を NVIDIA Blackwell GPU 上の機密コンピューティングモードで実行する形だ。これは、フロンティアのベンダーが信頼境界を保ったまま、自社の非公開推論をライバルのクラウドのシリコン上に置いた初めての事例である。この取り決めが成立するのは、ハードウェア自身がそれを証明できるからにほかならない。本物で改ざんされていない GPU 上でのリモートアテステーション、フリート内の全ノードを記録する暗号学的な台帳、公開バイナリの検査、そしてホスト先ノードにまで及ぶセキュリティ報奨金制度がそれを支える。本予測は、これが Apple 固有のエンジニアリング上の偉業にとどまらず、調達における基本要素(プリミティブ)になるというものだ。今後1年のうちに、少なくとももう一件のフロンティアベンダーまたはハイパースケーラーの推論の取り決めが、リモート GPU アテステーション、機密コンピューティングモード、検証可能なノード台帳を、マーケティング上の主張ではなく契約上で監査可能な条項として明記すると見込まれる。そうなれば機密コンピューティング対応ハードウェアは、セキュリティ機能から、非公開 AI 推論をどこで動かしてよいかを左右する商業上の関門へと変わる。これがチップベンダー、クラウド、モデル提供者を共通のアテステーション標準へと引き寄せていく。


   In plain language: Apple はいまや自社の非公開 AI を Google のコンピュータ上で動かしているが、それはチップが改ざんされていないと証明された後にのみ実現している。

### AI セキュリティがシリコンと交わる:Apple が Private Cloud Compute を、機密コンピューティング対応の Blackwell GPU 上で Google Cloud 上にて実行

- Apple は、プライバシーを強化した推論基盤である Private Cloud Compute を拡張し、Apple 管理外のデータセンターとして初めて Google Cloud 上で動かすことを明らかにした。Apple Foundation Models のサーバー側推論は、機密コンピューティングモードで動作する NVIDIA Blackwell GPU 上で実行される。NVIDIA は6月9日の投稿で、このセキュリティモデルを、本物で改ざんされていない GPU 上のハードウェアに根ざした信頼に、暗号化された通信経路とリモートアテステーションを加えたものと説明した。これにより、機密データを送る前にインフラが改ざんされていないことを暗号学的に検証できる。組み合わされた構成は、Blackwell の機密コンピューティングを Intel TDX CPU および Google の Titan セキュリティチップと結びつけ、Apple が言うエンドツーエンドの機密推論パイプラインを成す。 [NVIDIA Blog - NVIDIA Confidential Computing to help expand Apple's Private Cloud Compute](https://blogs.nvidia.com/blog/nvidia-confidential-computing-apple-private-cloud-compute/), [Apple Security Research - Expanding Private Cloud Compute](https://security.apple.com/blog/expanding-pcc/)

- この取り決めは、信頼境界における主導権を Apple に残す。端末は Apple が暗号学的に承認したソフトウェアしか信頼せず、暗号学的な台帳が PCC フリート内の Google Cloud の全ノードを追跡し、すべての PCC バイナリは公開検査のために公開され、Apple の Security Bounty も Google ホストのノードに及ぶ。この展開は2026年夏のプレビューを通じて段階的に拡大し、さらなる技術的な詳細は6月23~24日の Confidential Computing Summit で示される見込みだ。これは安全な AI アクセラレータという論点に対する具体的な裏付けである。証明済みでハードウェアの信頼の起点を備えた GPU 上での機密コンピューティング推論が、いまやフロンティアベンダーの非公開推論を第三者のデータセンターのシリコン上に置くために使われている。 [Help Net Security - Apple extends Private Cloud Compute to Google Cloud](https://www.helpnetsecurity.com/2026/06/10/apple-private-cloud-compute-google-cloud-expansion/)


### LLM 研究:エージェントを実行時生成のソフトウェアとして捉え直し、新ベンチマークがそのメモリが変化する世界に追従するかを検証

- 6月の arXiv 論文『Agentic Software: How AI Agents Are Restructuring the Software Paradigm』(arXiv:2606.05608)は、LLM エージェントがソフトウェアとは何かの根本的な再構成をなすと論じる。コードがあらかじめ書かれた判断ロジックを担うのではなく、エージェント自身がソフトウェアであり、その判断ロジックは実行時に生成される。著者はこれを、ライセンス販売型ソフトウェアから SaaS、そして agent-as-a-service への移行と位置づける。これは今週のツール関連ニュースの概念的な対をなし、コードをその場で生成しては捨てるコーディングエージェントが、なぜ決定論的なプログラムとは異なる振る舞いをするのかを定式化している。 [arXiv - Agentic Software: How AI Agents Are Restructuring the Software Paradigm](https://arxiv.org/abs/2606.05608)

- 実証面では、EvoArena(arXiv:2606.13681、6月11日)が、環境が変化するにつれてエージェントが知識の整合を保てるかを検証する。変化を、ターミナル・ソフトウェア・ソーシャルの各領域にわたる段階的な更新の連なりとしてモデル化する。現行のエージェントの成績は振るわず、こうした変化していく状況での平均正答率は39.6%にとどまる。著者らは EvoMem を提案する。これはメモリを構造化された更新履歴として記録するパッチ方式のメモリ手法で、EvoArena を平均1.5%引き上げつつ、標準的な GAIA と LoCoMo のベンチマークもそれぞれ6.1%、4.8%改善したと報告されている。この結果は、静的なベンチマークは長時間動作するエージェントの頑健さを過大評価する、という繰り返し現れる指摘をいっそう鮮明にする。 [arXiv - EvoArena: Tracking Memory Evolution for Robust LLM Agents in Dynamic Environments](https://arxiv.org/abs/2606.13681)
