- **Nagdala ang AMD ng native ROCm support sa vime, ang RL post-training framework ng vLLM; end-to-end nang tumatakbo ang open-model RL sa Instinct MI355X** — Sinabi ng vLLM project noong July 10 na ang vime — ang reinforcement-learning post-training framework nito — ay tumatakbo na ngayon nang end-to-end sa mga AMD Instinct MI355X GPU sa pamamagitan ng native ROCm support, isang port na iniambag ng mga AMD contributor at inihatid bilang prebuilt Docker container na nag-aalis sa from-source build na matagal nang humahadlang sa pag-adopt ng ROCm. Hinahati ng vime ang isang RL run sa decoupled na pipeline — model training sa Megatron, generation at rollout sa vLLM, at isang data buffer sa pagitan ng dalawa — kaya ang serving engine na naging default para sa open-model inference ay nagpapatakbo na rin ngayon ng reward loop. Sa Qwen3-4B, Qwen3-8B, at Qwen3-30B-A3B mixture-of-experts na modelo, nanatili ang throughput malapit sa 4,100 token kada GPU kada segundo sa 100 training step, nanatili sa palibot ng 0.012 ang log-probability divergence sa pagitan ng training at rollout, at umakyat ang reward mula halos sero patungong 0.5-0.6 pagsapit ng step 100 — ang mga senyales ng numerical stability at convergence na sinusuri ng isang lab bago magtiwala sa non-NVIDIA na silicon. Dahil ang RL post-training, hindi ang pre-training, ang pinagpipigaan ng karamihan sa mga frontier gain ngayong taon at halos buong nakatali sa CUDA, ang gumaganang MI355X na landas ay nagbibigay sa mga open-model builder ng tunay na ikalawang hardware vendor para sa kanilang pinaka-gutom-sa-compute na yugto. - **Nagtatanim ang MemGhost ng mga permanenteng huwad na memory sa mga personal AI agent sa pamamagitan ng iisang email** — Inilarawan ng isang team mula sa Nanyang Technological University, sa CFAR ng A*STAR, at sa Johns Hopkins ang MemGhost — isang teknik na nagpapalason sa long-term memory ng isang personal AI agent gamit ang isang crafted na email — sa isang papel na inilathala sa arXiv noong July 6 at kinuha sa security coverage noong July 13. Kapag natanggap ng isang agent na bumabasa ng inbox ng may-ari nito ang mensahe, inuudyok itong isulat ang mga 'fact' na pinili ng umaatake sa mga persistent memory file nito, magbalik ng inosenteng tugon na nagpapakitang walang nangyari, at hayaang patnubayan ng mga itinanim na fact na iyon ang gawi nito sa mga susunod at walang-kaugnayang session. Sinukat ito sa WhisperBench, isang 108-case na benchmark na sumasaklaw sa fact at preference poisoning sa isang live na IMAP/SMTP email workflow, at nagtagumpay sa 87.5% ng mga background-mode run laban sa open-source na OpenClaw agent sa GPT-5.4 at 71.4% laban sa isang Claude Code SDK agent sa Sonnet 4.6, na lumipat sa iba't ibang agent architecture at memory backend. Walang malinis na patch: ang mga iminungkahing depensa — pag-tag sa provenance ng bawat naka-imbak na fact, user approval bago ang isang memory write, at pag-log sa lahat ng pagbabago sa memory — ay mga pagbabagong arkitektural sa halip na isang switch na maii-flip ng user, na nagre-reframe sa agent memory bilang isang hindi-naa-audit na persistence layer na kayang sulatan ng isang tagalabas. [arXiv - When Claws Remember but Do Not Tell: Stealthy Memory Injection in Persistent Personal Agents](https://arxiv.org/abs/2607.05189), [The Hacker News - New MemGhost Attack Plants Persistent False Memories in AI Agents Through One Email](https://thehackernews.com/2026/07/new-memghost-attack-plants-persistent.html)

- **Ginagawang sandata ng GhostApproval ng Wiz ang symlink para ilihis ang file write ng AI coding agent patungo sa SSH keys; nagkahati ang anim na vendor** — Pampublikong inihayag ng Wiz Research ang GhostApproval noong July 8, isang trust-boundary na depekto na ginagawang repository-borne na atake ang isang ilang-dekadang symbolic link laban sa mga AI coding assistant. Naglalaman ang isang malisyosong repo ng file na may inosenteng pangalan tulad ng project_settings.json na sa totoo ay isang symlink na nakaturo sa ~/.ssh/authorized_keys; kapag hiniling ng developer sa agent na i-set up ang workspace at inaprubahan ang mukhang inosenteng config edit, sa halip ay napupunta ang write sa SSH file, na nagtatanim ng key ng umaatake para sa passwordless na remote access. Ang pangunahing pagkabigo ay isang consent bypass: nagpapakita lamang ang approval dialog ng benign na filename, hindi ang na-resolve na sensitibong path. Iniulat ito ng Wiz sa anim na vendor — Amazon Q Developer, Claude Code ng Anthropic, Augment, Cursor, Google Antigravity, at Windsurf; naglabas ng fix ang Amazon (CVE-2026-12958), Cursor (CVE-2026-50549), at Google Antigravity, habang nanatiling hindi na-patch ang Augment at Windsurf noong disclosure at itinanggi ng Anthropic na bug ang gawi ng Claude Code, na iginigiit na pag-aari ng developer na nagtitiwala sa isang directory ang desisyon. ### Predictions check

Umiikot ang cycle ngayon sa iisang security disclosure na muling nag-aayos sa grupo ng coding-agent: ang July 8 GhostApproval na natuklasan ng Wiz Research. Dito, naglalabas ang isang malisyosong repository ng file na may mukhang-inosenteng pangalan — project_settings.json — na sa totoo ay isang symbolic link patungo sa ~/.ssh/authorized_keys. Kaya ang developer na nag-aaprubahan sa mukhang walang-anumang config edit ay hindi sinasadyang nagtatanim ng key ng attacker at nagbibigay ng passwordless na remote access. Ang pagkabigo ay isang consent bypass: ipinapakita lang ng approval dialog ang inosenteng filename, hindi kailanman ang na-resolve na destinasyon. Iyon ang ebidensya ng pinagmulan ng sariwang forecast ngayon na 'AI coding assistants make symlink-aware write consent the default' (July 12), at ang tugon ng anim na vendor ang hindi maiiwasang salik nito — naglabas ng fix ang Amazon Q Developer (CVE-2026-12958), Cursor (CVE-2026-50549), at Google Antigravity na nireresolba at ipinapakita ang tunay na path, hindi pa na-patch ang Augment at Windsurf noong disclosure, at itinanggi ng Anthropic na bug man lang ang gawi ng Claude Code, na nangangatwirang ang developer na nagtitiwala sa isang directory ang may-ari ng desisyong iyon. Ang hating hatol — kalahati ng larangan na itinuturing na depekto ang tahimik na pagsunod sa symlink habang inilalagay ng isang vendor ito sa labas ng threat model nito — ang tunay na kuwento, at ito mismo ang kawalan ng linaw na inaasahan ng prior na 'agent-sandbox isolation becomes a named procurement requirement' (July 7) na lulutasin ng wika sa panig ng mamimili.

Kumakalat ang GhostApproval sa lahat ng nakatayong security forecast ng linggo, na lahat ay tumuturo sa iisang nawawalang primitive — nasa harness at sa approval gate nito ang matagalang mitigasyon, hindi sa modelo. Pinatitibay nito ang forecast na 'coding agents ship default-deny sandboxes for untrusted-repo audits' (July 11) bilang isa pang untrusted-repository na atake na ginagawang armas ang isang agent habang karaniwang inaayos ang workspace. At ito mismo ang allowlist-at-approval na kontrol na inaasahan ng forecast na 'LLM client libraries ship a permission-gated coding-agent loop' (July 8) na magiging first-class primitive, bagaman ang mga fix ngayon ay inilalabas sa loob ng mga produktong tulad ng Claude Code at Cursor, hindi sa pinangalanang client libraries. Ang parehong-linggong pag-patch ng Amazon at Google sa sarili nilang coding agent ay pumapasok sa prior na 'agent-runtime security folds into a hyperscaler-native defense tier' (July 7), na nagpapatunay na ang mga may-ari ng platform na inaatake ang runtime ang may hawak ng insentibo para akuin ang tugon. Dalawang dormant na longshot ang muling nabubuhay sa parehong senyales: ang longshot na 'Agent-in-the-Loop Secret Exfiltration tops CIS and OWASP risk lists' (April 20), dahil ang GhostApproval ay isang high-profile na agent-mediated na credential-exfiltration na pangyayari sa anim na assistant, at ang longshot na 'coding-agent platform ships trifecta capability gate as default' (June 28), na binabasa ang atake bilang tipikal na lethal-trifecta na kadena ng untrusted na nilalaman, file-write access, at panlabas na komunikasyon. Sa lahat ng mga ito, pangangailangan ang ibinibigay ng araw na ito, hindi paglalabas — tatlong write-path na fix, walang magkakatulad na default, at wala ring attestation log o capability gate.
