- **Iisang prompt ang nakatakas sa lokal na VM ng Claude Cowork; sumakay ang mga pekeng ad sa claude.ai** — Inihayag ng Accomplish AI ang SharedRoot noong July 23, isang pagtakas mula sa Linux VM na ginagamit ng Claude Cowork para sa lokal na pagpapatakbo sa macOS, at kasya ang buong kadena sa iisang prompt: tinatawag ng hindi-priyibilehiyadong session user ang unshare para lumikha ng user namespace, kinukuha ang CAP_NET_ADMIN sa loob nito, isinasaayos ang isang traffic-control action laban sa mahinang act_pedit module, at pinagsasamantalahan ang CVE-2026-46331 — ang pedit copy-on-write na out-of-bounds write sa kernel traffic-control subsystem, na binibigyan ng Red Hat ng 7.8 — para lasunin ang page cache ng isang binary na pag-aari ng root. Kapag muling ipinatakbo ng coworkd daemon ang binary na iyon, tumatakbo ang payload bilang guest-root. At dahil naka-mount nang read-write ang buong host filesystem papasok sa guest sa /mnt/.virtiofs-root, ang guest-root ay akses na sa host: mga SSH key at cloud credential na malayo sa folder na talagang ikinabit ng user. Ayon sa The Hacker News, mga 500,000 macOS user ang nasa lokal na session sa panahon ng pagkakalantad. Isinara ng Anthropic ang ulat bilang impormatibo nang walang ipinadalang ayos, na binabanggit ang exclusion window ng bounty program para sa mga CVE na nailathala sa nakalipas na 30 araw, kaya isang product default at hindi isang patch ang naiwang mitigasyon dahil sa cloud tumatakbo ang mga kasalukuyang build. Lumalampas sa iisang vendor ang istrukturang aral: ang pag-mount ng host filesystem nang read-write papasok sa guest ng isang agent ay ginagawang kompromiso sa host ang bawat karaniwang local-privilege-escalation bug sa kernel ng guest.
